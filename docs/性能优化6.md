# 性能优化6：体系化大优化方向筛选

本文档接替 `性能优化5.md`，用于调研、规划并记录 perf6 阶段值得实现的重大优化。本轮重点不是继续堆零散 peephole，而是在已经完成 perf5 的基础上，重新检查当前项目、`hy` 参考项目和历史撤回记录，筛出能影响多个 benchmark、能解锁后续优化、并且有明确依赖和风险边界的体系化大优化。

本轮结论：当前剩余热点已经从递归热点转向矩阵、stencil、transpose、shuffle 等循环和地址计算密集型用例。下一轮不应重复 perf5 中已经验证负向的“全局 LCSSA / 裸 MachineDCE / 裸 offset combine / 无承接 SCEV”，而应先补可观测、可回滚的 O2 优化闭环，再推进完整 GVN/ADCE、按需循环规范化和 SCEV 地址递推。机器级 cleanup 仍重要，但必须先建立命中统计和寄存器压力保护。

## 3. 当前已有优化总结

当前 `-O1` 管线在 `src/main.cpp` 中实际注册顺序如下：

```text
Verify
  -> SimplifyCFG
  -> Mem2Reg
  -> SingleStoreAlloca
  -> InlineSimpleFunction
  -> RuntimeMemoize
  -> TailCallOpt
  -> ConstantFold
  -> LocalCSE
  -> LocalStoreForward
  -> DLE
  -> DSE
  -> SimplifyCFG
  -> TrivialPhi
  -> SimplifyCFG
  -> LoopCanonicalize
  -> LoopClosedForm
  -> SimplifyCFG
  -> LICM
  -> LocalCSE
  -> LocalStoreForward
  -> DLE
  -> DSE
  -> DCE
```

每个关键 transform 后都插入了 `VerifyPass`，这是当前项目稳定性的优势。当前 pass manager 仍是固定顺序执行，pass 自身不向 manager 返回 changed 信息，因此还没有真正的 O2 fixpoint 或按收益启停机制。

| 层级 | 已有优化 | 当前状态判断 |
| --- | --- | --- |
| CFG | `SimplifyCFGPass` 可折叠常量分支、phi/icmp 分支中转块、删除不可达块、bypass 空跳转块 | 可用，但不是完整 CFG simplify；缺 general jump threading、系统 block merge、后端布局优化 |
| SSA / mem2reg | `Mem2RegPass` 基于支配边界插 phi，沿 dominator tree rename；只提升 int/float 标量 alloca | 标量 SSA 比较完整；数组、指针、地址逃逸不提升是正确边界 |
| Phi 清理 | `TrivialPhiPass` 删除所有 incoming 相同的 phi；后端 Phi register lowering 使用稳定机器 vreg 和边拷贝 | 基础清理和后端承接较好；缺更强 parallel copy 环处理和 LCSSA exit phi 清理 |
| 常量折叠 | `ConstantFoldPass` 支持 int/float 常量二元、整数恒等式、同值比较、`zext`、只读全局标量 load、布尔分支规约 | 简单折叠可用；缺 SCCP、range-aware fold、跨 CFG 常量边删除 |
| CSE/GVN | `LocalCSEPass` 沿支配树复用纯表达式，覆盖 binary/icmp/fcmp/zext/cast/gep；perf5 已加入 `add/mul` 和 `icmp eq/ne` 交换律 key | 已超过单块 CSE，但仍不是完整 GVN；缺 value number、phi numbering、纯 call、内存表达式和更强 GEP 规范 |
| DCE | `DCEPass` 删除无 use 且无副作用的纯指令 | 只是普通 DCE；perf5 的 ADCE-only 和固定 cleanup round 功能正确但未证明性能收益，已撤回 |
| 内存优化 | `MemoryAlias` base+offset；`DLE` 可用 load dataflow；`DSE` 同块覆盖 store、同值 store、未逃逸局部数组 backward DSE；`LocalStoreForward` 同块 exact pointer 前递 | 保守可用；unknown offset/call/形参别名边界严格；缺 InlineStore、循环内存标量替换、dead global store、只读数组合成 |
| 循环基础 | `LoopAnalysis` 自然循环；`LoopCanonicalizePass` 补 preheader，并在 perf5 保留 dedicated exit splitting 子集 | 比 perf4 更进一步，但 LCSSA 已因 `crypto-*` timeout 撤回，LoopRotate 因前置不满足暂缓 |
| LICM | `LICMPass` 外提安全纯计算、GEP、比较、cast、zext；可外提无 call 且函数无 store 的全局标量 load | 保守可用；不会外提普通 load，不用 alias，不做寄存器压力模型；alias-LICM 曾回退 |
| 循环特化 | `LoopClosedFormPass` 闭式替换窄模式全局标量递推 | 对 `conv2d` 很有效，但模式非常窄；不是通用 SCEV |
| 函数优化 | `InlineSimpleFunctionPass` 内联单块小纯函数；`RuntimeMemoizePass` 有界二参重叠自递归 memo；`TailCallOptPass` 已把直接 self tail call 转循环 | 特判收益很大；缺调用图驱动 inline、late inline、参数常量特化和互递归/间接尾调用优化 |
| 后端指令选择 | `InstructionSelector` 做小立即数 add/sub、乘 0/1/-1/2^k、除 1、模 1/-1、GEP scale `slli`、compare-branch fusion、GEP prefix cache、local value cache、helper equivalence | 已有多项高收益 lowering 优化；缺独立机器级 InstCombine/StrengthReduction/RvDCE 的稳定版本 |
| 寄存器分配 | 图着色 RA；GPR 使用 `t0-t6 + s1-s11`；call-live GPR 限制到 callee-saved；COPY coalescing 和 affinity coloring；按实际使用保存恢复 `s*` | 比早期完整很多；spill 仍是直接 reload/store，FPR callee-saved、rematerialization、spill 合并较弱 |
| 栈帧/汇编 | 紧凑 SP-relative epilogue；`MachineAsmLowering` 删除同寄存器 COPY | 返回路径已优化；缺基本块布局、post-RA cleanup、机器级死定义删除 |
| Pipeline | 固定两轮 memory cleanup 和 loop 后 cleanup；每步 verify | 有顺序但不是 O2 fixpoint；perf5 证明“直接加固定多轮 cleanup”不稳定，需要先做 changed/stats/成本门控 |

当前实现比较完整的优化：

- `Mem2RegPass` 对标量 alloca 的 SSA 提升。
- `SimplifyCFGPass` 的常量分支、不可达块和部分中转块清理。
- `LocalCSEPass` 的 dominator-scoped 纯表达式复用。
- 后端 GPR 图着色、callee-saved GPR、COPY coalescing、Phi register lowering、compare-branch fusion、GEP prefix cache 和 local value cache。
- `RuntimeMemoizePass`、`LoopClosedFormPass`、`TailCallOptPass` 这几类已命中大热点的窄模式优化。

当前实现比较浅、仍有提升空间的优化：

- `LocalCSEPass` 还不是完整 GVN。
- `DCEPass` 不是 ADCE，pipeline 也没有可控 cleanup fixpoint。
- `LoopCanonicalizePass` 只有 preheader + dedicated exit 子集，LCSSA 和 LoopRotate 未稳定。
- `LICMPass` 不使用 alias 外提普通 load，也没有成本模型。
- 内存优化仍以 exact/base+offset 为边界，缺跨迭代和跨块更强前递。
- 后端机器级 cleanup 曾尝试但负优化，说明缺统计和 RA 压力保护。

当前明显缺失的关键优化：

- 可观测、可门控的 O2 pass pipeline。
- 完整 GVN / value numbering。
- ADCE 作为大优化后的 cleanup 安全网。
- 通用 SCEV 地址递推 / loop strength reduction。
- 按需 LCSSA / LoopRotate，而不是全函数无差别 LCSSA。
- 循环内存标量替换。
- Late inline + inline 后二次优化闭环。
- Spill rematerialization 和后端压力统计。

当前 pipeline 的体系性问题：

- 大优化后缺少统一 cleanup 闭环，但 perf5 证明不能直接固定插多轮 cleanup。
- pass 不暴露 changed/stats，无法做 fixpoint、无法按收益和命中规模控制。
- inline、memo、TCO 后只有一轮 Fold/CSE/memory cleanup，缺完整 GVN/ADCE。
- loop pass 只有一次，且 SCEV/A1/D2 依赖的 LCSSA/LoopRotate 未稳定。
- 机器级优化都在 selector/RA 周边零散完成，缺独立但受控的机器 cleanup。

| --- | --- | --- | --- |
| Pipeline 分层 | structured pre-opt、flatten 后 GVN/DCE/Inline、Mem2Reg 后 Alias/DSE/DLE/GVN、Loop、Misc、LateInline、三轮 loop cleanup、FinalCleanup、RV cleanup | 当前是一条固定 O1 管线，缺 changed/stats、缺可控 fixpoint、缺 late inline 后完整 cleanup | 强烈建议借鉴“分阶段 + 小轮次收敛 + 大优化后 cleanup”，但不能照搬结构化 IR |
| CFG/Loop 形态 | `CanonicalizeLoop(lcssa)`、`LoopRotate`、`RemoveEmptyLoop` 多轮使用 | 当前只有 preheader + dedicated exit 子集；LCSSA 撤回，LoopRotate 暂缓 | 建议改成“按需构造给 D1/A1 使用”，避免重做全函数 LCSSA |
| 标量全局优化 | `GVN` 基于支配树值编号，`AggressiveDCE` 反向标记 live，`RegularFold` 多轮清理 | 当前 LocalCSE 不是完整 GVN，ADCE 撤回，cleanup 无门控 | 建议优先做完整 GVN 和更窄 ADCE cleanup |
| 循环强优化 | `SCEV` 识别归纳变量和地址递推，`ConstLoopUnroll`，多轮 `LICM -> SCEV -> GVN -> Fold` | 当前只有窄 `LoopClosedFormPass`，通用 D1 因依赖未满足暂缓 | 建议作为核心 P0，但必须先有 P0 的 pipeline/GVN/按需 loop shape |
| 内存优化 | 多轮 `Alias -> DSE -> DLE`，另有 `DAE`、`InlineStore`、`SynthConstArray` | 当前 DLE/DSE 保守可用，但缺跨块/跨迭代前递、循环内存标量替换、常量数组 | 建议先做 A1/A2 的保守子集，常量数组放 P2 |
| 函数优化 | `EarlyInline`、`Inline`、`LateInline`、`TCO` | 当前 TCO 已完成直接 self tail call；inline 仍只支持单块小纯函数 | 建议把 LateInline 放 P1，必须接 GVN/ADCE cleanup |
| RISC-V 后端 | `StrengthReduct -> InstCombine -> RvDCE -> GVN -> RegAlloc`；RegAlloc 内有 late peephole/tidyup | 当前 selector 有很多规则，但 E1a/E1b 机器 pass 曾功能过但性能负向 | 建议先补统计和压力模型，再做白名单机器 cleanup |
| 结构化 pre-opt | `RaiseToFor`、`ColumnMajor`、`Fusion`、`Parallelizable`、`TidyMemory` | 当前项目直接生成 LLVM 风格 BasicBlock IR，缺结构化中间层 | 不建议短期照搬 |

hy 可借鉴点：

- `src/main/main.cpp` 的分层顺序非常有价值：大优化之间反复用 GVN/Fold/DCE/SimplifyCFG 清理，而不是只跑一次。
- `GVN.cpp` 的 value numbering 思路适合替代当前基于 Value 指针 key 的 LocalCSE。
- `AggressiveDCE.cpp` 适合重做为大优化后的 cleanup pass，但当前项目必须先加统计和启停控制。
- `CanonicalizeLoop.cpp`、`LoopRotate.cpp`、`SCEV.cpp` 的算法方向适合 D1，但当前不能全局照搬 LCSSA/LoopRotate。
- `rv/StrengthReduct.cpp`、`rv/InstCombine.cpp`、`rv/RvDCE.cpp` 说明 RISC-V 后端 cleanup 是完整体系的一部分，但 perf5 证明当前项目需要更保守的成本模型。

hy 不适合直接照搬的点：

- hy 的 IR 是 Op/Region 风格，当前项目是 BasicBlock/Instruction 风格；代码结构不能直接搬。
- hy 的结构化 pre-opt 依赖 flatten 前的结构化控制流，当前项目没有这个中间层。
- hy 的 GCM 和 SCEV 依赖更完整 loop info、GVN、ADCE 和后端承接；当前裸上已在历史中回退。
- hy 的 signed div/rem magic number 降强语义复杂，当前不能在没有逐条 RISC-V 功能验证和统计的情况下引入。

## 6. 详细优化方案

### O1 可观测 O2 pipeline 与 cleanup 门控

- 优先级：P0。
- 当前项目状态：`IRPassManager` 固定顺序执行，每个 pass 的 `run(Module&)` 只返回是否成功，不返回 changed；perf5 曾尝试固定加入 ADCE/cleanup round，功能正确但性能未证明收益，最终撤回。
- hy 参考：`Testing/Hycompiler/src/main/main.cpp` 中多阶段 pipeline，以及多轮 `GVN -> RegularFold -> DCE/AggressiveDCE -> SimplifyCFG` 的组织方式。
- 当前问题：没有 changed/stats 就无法做真正 fixpoint，也无法限制 cleanup 轮次和命中规模；大优化后缺清理，但无门控清理又会扰动 RA 和热点。
- 优化目标：建立可观测 O2 框架，支持 pass 记录 changed、删除/替换数量、IR 指令数变化、基本块数变化；大优化后按小轮次和上限运行 cleanup，而不是无条件固定多轮。
- 实现思路：先不改变优化内容，只扩展 pass 统计接口或在 manager 外部统计 IR 指令数；新增 `runCleanupRound(maxRounds, budget)` 的概念；cleanup 顺序先限制为 `ConstantFold -> TrivialPhi -> LocalCSE/GVN -> DCE/ADCE -> SimplifyCFG`，但每轮记录变化并可停止。
- 涉及模块：`IRPassManager.*`、`IRPass.*`、各 pass 的 changed/stats 返回、`src/main.cpp`。
- 前置依赖：无强依赖，适合作为 perf6 第一项。
- 预期收益：单独可能 0%-2%；主要收益是让 B2/D1/A1/F1 的优化产物能稳定收敛，避免 perf5 B1 的无门控负优化。
- 风险点：改 pass 接口会触及多个文件；统计本身不能改变 IR；如果直接改变 pipeline 仍可能扰动性能。
- 功能测试：接口调整后先跑 `compiler2026-riscv-function` `140/140`；增加空 pass / changed pass 的小测试。
- 性能测试：先用不改变 pipeline 的统计版跑 perf，确认 timer 不明显变化；再逐步启用门控 cleanup。
- 建议执行顺序：统计接口 -> 不改行为验证 -> 只在大优化后手动调用一轮 cleanup -> 再考虑小 fixpoint。
- 是否建议实现：建议优先实现。

### B2 完整 GVN + 更窄 ADCE cleanup

- 优先级：P0。
- 当前项目状态：`LocalCSEPass` 已沿支配树做表达式复用，perf5 的 B2a 交换律 key 两轮平均 `-1.20%`；但它仍基于 Value 指针 key，不是真正 value numbering。ADCE-only 曾撤回，说明 ADCE 不能单独裸上。
- hy 参考：`Testing/Hycompiler/src/opt/GVN.cpp`、`Testing/Hycompiler/src/opt/AggressiveDCE.cpp`、`Testing/Hycompiler/src/opt/RegularFold.cpp`。
- 当前问题：D1/F1/D2 之后会产生等价但 Value 指针不同的表达式；当前 LocalCSE 吸收不干净。普通 DCE 删不掉互相引用的死 phi/死表达式。
- 优化目标：实现函数级 value numbering，覆盖常量、binary、icmp/fcmp、cast/zext、GEP、trivial phi；ADCE 只作为 cleanup round 的一部分，优先删除纯指令子图，不主动改 terminator。
- 实现思路：复用支配树 DFS；为每个 Value 分配 number；交换律 op 按 value number 排序；GEP key 包含 base number、index number、result type；第一版不处理 load/call；ADCE 用 live root 反向标记，未知 call/store/terminator 保守 live。
- 涉及模块：新增或升级 `GVNPass` / `LocalCSEPass`，新增更窄 `ADCEPass`，`IRCFG`、`SimplifyCFGPass`、`TrivialPhiPass`。
- 前置依赖：O1。
- 预期收益：3%-10%；重点吸收矩阵地址表达式、inline 后 helper、SCEV 产生的重复计算。
- 风险点：把非纯 op 纳入 GVN 会错编；phi numbering 必须处理循环和不可达 incoming；ADCE 不能删除必要控制流。
- 功能测试：交换律、不交换律、GEP 等价/不等价、trivial phi、死 phi 环、load/call 负例、不可达块。
- 性能测试：2026 perf，重点观察 `many_mat_cal-*`、`sl*`、`matmul*`、`transpose*`、`crypto*`。
- 建议执行顺序：纯 scalar/GEP GVN -> trivial phi value number -> O1 cleanup 接入 -> 窄 ADCE。
- 是否建议实现：建议优先实现。

### C2 按需 LoopSimplify：目标循环 LCSSA/Rotate/exit 形态

- 优先级：P0。
- 当前项目状态：`LoopCanonicalizePass` 已有 preheader 和 dedicated exit splitting 子集；perf5 C1a 保留。全局 LCSSA 候选功能 `140/140`，但 `crypto-1/crypto-2` perf run timeout，已撤回；LoopRotate 因 LCSSA 前置未满足暂缓。
- hy 参考：`Testing/Hycompiler/src/opt/CanonicalizeLoop.cpp`、`Testing/Hycompiler/src/opt/LoopRotate.cpp`、`Testing/Hycompiler/src/opt/RemoveEmptyLoop.cpp`、`Testing/Hycompiler/src/opt/LoopPasses.h`。
- 当前问题：D1/A1/D2 需要稳定 loop shape，但全函数无差别 LCSSA 已证明风险过高。需要转为“只为目标循环构造必要形态”。
- 优化目标：为 D1/A1 的候选循环按需保证 preheader、single latch、dedicated exit、必要 exit value phi；只旋转低风险、单 latch、单 exit、低 phi 数循环。
- 实现思路：不要恢复 perf5 C1b 的全局 LCSSA；先在 D1 候选分析中返回“缺什么形态”，再由 C2 对单个候选循环做最小修补；每次只改一个 loop 并立即 Verify。
- 涉及模块：`LoopAnalysis.*`、`LoopCanonicalizePass.*`、`IRCFG.*`、`PhiInst.*`、`VerifyPass.*`。
- 前置依赖：O1；B2 更稳。
- 预期收益：直接 0%-2%；主要解锁 D1/A1/D2，并避免全局 LCSSA 的 timeout。
- 风险点：phi incoming 修补、exit value rewrite、LoopRotate 改变后端布局和 live range。
- 功能测试：零迭代、单次迭代、break/continue、多 exit、嵌套循环、exit phi、loop-defined value 外用。
- 性能测试：先要求不明显退化；如果只作为 D1 内部前置，和 D1 一起看命中率和收益。
- 建议执行顺序：候选循环筛选 -> 最小 dedicated shape 检查 -> 按需 LCSSA phi -> 低风险 rotate。
- 是否建议实现：建议优先，但必须按需，不建议重做全局 LCSSA。

### D1 SCEV 地址递推 / loop strength reduction

- 优先级：P0。
- 当前项目状态：缺通用 SCEV；只有 `LoopClosedFormPass` 针对 `conv2d/get_random` 的窄闭式化。perf5 因 B1/E1/C1 依赖未满足暂缓 D1。
- hy 参考：`Testing/Hycompiler/src/opt/SCEV.cpp`、`Testing/Hycompiler/src/opt/LoopUnroll.cpp`、`Testing/Hycompiler/src/rv/StrengthReduct.cpp`。
- 当前问题：当前最大热点组 `many_mat_cal/sl/matmul/01_mm/transpose` 大量重复计算 `base + i * stride + j`；后端 GEP prefix cache 只能复用同一基本块内前缀，不能跨迭代递推。
- 优化目标：识别 `i = phi(start, i + step)`、常量 stride、退出比较和低风险 trip count，把循环内重复 GEP 乘加改为 loop-carried 递推地址，或外提 row base/scale。
- 实现思路：第一版只处理 int32 常量 step、单 latch、单 exiting、无复杂 call 的循环；优先做 row-base 外提和单层 GEP 递推，不急于替换普通算术；新增 phi 后立刻调用 O1/B2 cleanup。
- 涉及模块：`LoopAnalysis`、C2 形态修补、`GetElementPtrInst`、`BinaryInst`、`PhiInst`、`LICMPass` 或新增 `SCEVPass`。
- 前置依赖：O1、B2、C2；E2 的统计可以并行准备。
- 预期收益：5%-15%；重点 `many_mat_cal-*`、`sl*`、`matmul*`、`transpose*`、`01_mm*`。
- 风险点：新增 phi 增加寄存器压力；地址 offset 错误会错编；有符号溢出和零迭代语义要保守；历史 D1 曾因缺承接暂缓。
- 功能测试：二维/三维数组、不同 stride、零迭代、单次迭代、嵌套循环、负 step 负例、有 call/store 的负例。
- 性能测试：以 perf5 final 或实现前同环境 baseline 为准；逐项记录矩阵/stencil/transpose 变化。
- 建议执行顺序：row-base 外提 -> 单层 GEP 递推 -> 嵌套 row pointer 递推 -> 和 A1/D2 组合。
- 是否建议实现：建议优先实现。

### E2 后端压力统计 + 白名单机器 cleanup/remat

- 优先级：P1。
- 当前项目状态：perf5 的 E1a MachineDCE 和 E1b offset combine 功能均 `140/140`，但性能均慢于 C1a，已撤回。当前 RA 有 callee-saved GPR、coalescing 和 affinity；spill 仍是直接 reload/store。
- hy 参考：`Testing/Hycompiler/src/rv/StrengthReduct.cpp`、`Testing/Hycompiler/src/rv/InstCombine.cpp`、`Testing/Hycompiler/src/rv/RvDCE.cpp`、`Testing/Hycompiler/src/rv/RegAlloc.cpp`。
- 当前问题：机器级 cleanup 是 hy pipeline 的关键组成，但当前项目裸 MachineDCE/offset combine 会扰动 RA，出现负优化。必须先知道命中位置、指令数、live range 和 spill 变化。
- 优化目标：建立后端统计：机器指令数、`li/mv/add/load/store/div/rem` 数、spill slot 数、reload/store 数、最大 liveOut；再只对白名单模式做 rematerialization 或 cleanup。
- 实现思路：第一阶段只输出统计，不改机器 IR；第二阶段只做常量/zero/小立即数 rematerialization，避免 reload；第三阶段再尝试 signed 安全的 strength reduction 子集。
- 涉及模块：`MachineIR`、`MachineCFG`、`MachineLiveness`、`GraphColoringRegisterAllocator`、`MachineLegalizer`。
- 前置依赖：O1 可共享统计思路；D1 后更能看到真实压力。
- 预期收益：1%-6%；主要承接 D1/A1/D2，防止 IR 大优化被栈流量抵消。
- 风险点：再次重现 E1a/E1b 负优化；remat 如果跨 call/side effect 处理错会错编；signed div/rem 语义风险高。
- 功能测试：call-heavy、float、大栈帧、spill 压力、递归、多返回块。
- 性能测试：2026 perf；同时记录统计项变化，不只看总 timer。
- 建议执行顺序：统计-only -> 常量 remat -> reload/store 合并 -> 小白名单 strength reduction。
- 是否建议实现：建议，但不要作为 perf6 第一项裸上。

### A1 循环内存标量替换 / invariant address scalar replacement

- 优先级：P1。
- 当前项目状态：缺失；`DLE/DSE/LocalStoreForward` 只能处理局部或 dataflow 可证明的 load/store，不能把循环内固定地址 load-compute-store 变成 scalar phi。
- hy 参考：`Testing/Hycompiler/src/opt/LICM.cpp`、`Testing/Hycompiler/src/opt/InlineStore.cpp`、`Testing/Hycompiler/src/opt/DLE.cpp`、`Testing/Hycompiler/src/opt/DSE.cpp`。
- 当前问题：矩阵、stencil、归约类循环中存在跨迭代固定地址或可证明不别名地址的重复 load/store；当前优化只能做局部前递。
- 优化目标：对不逃逸 local alloca 或精确 base+offset，在 preheader load 成 scalar，循环内用 phi/update，exit 写回。
- 实现思路：先只处理单 exit、单 store、无 may-alias call、无 unknown offset 的 local alloca 精确位置；全局和形参地址后置。
- 涉及模块：`MemoryAlias`、`LoopAnalysis`、C2、`DLEPass`、`DSEPass`、`PhiInst`。
- 前置依赖：C2、B2、D1、O1。
- 预期收益：3%-10%，重点 `sl*`、`many_mat_cal-*`、`matmul*`。
- 风险点：alias 证明不足会错编；exit 写回位置和零迭代语义复杂；会增加 phi 和寄存器压力。
- 功能测试：reduce、stencil、小矩阵、early exit、break/continue、别名形参负例、零迭代。
- 性能测试：2026 perf，重点矩阵/stencil 组；同步观察 E2 spill 统计。
- 建议执行顺序：未逃逸 local alloca -> 精确 GEP -> loop-carried scalar -> exit store。
- 是否建议实现：建议，但不要早于 C2/B2/D1。

### F1 Late inline + inline 后二次优化管线

- 优先级：P1。
- 当前项目状态：`InlineSimpleFunctionPass` 只内联单基本块、最多 8 条纯计算指令；后端 helper equivalence 能识别 bitwise/add/sub/modmul/minmax，但 IR 层看不到 inline 后常量传播和 GVN 机会。
- hy 参考：`Testing/Hycompiler/src/pre-opt/EarlyInline.cpp`、`Testing/Hycompiler/src/opt/Inline.cpp`、`Testing/Hycompiler/src/opt/LateInline.cpp`。
- 当前问题：继续加 helper 采样特判泛化差；更体系化的方式是扩展 IR inline，然后由 B2/O1 cleanup 吸收。
- 优化目标：基于调用图和成本模型做 small multi-block pure helper late inline；inline 后运行 `Fold/GVN/ADCE/SimplifyCFG` 门控 cleanup。
- 实现思路：先只支持无 store、无 impure call、非递归、小基本块数、单 return 合流的 helper；递归和大函数跳过。
- 涉及模块：`InlineSimpleFunctionPass`、`CallInst`、`BasicBlock` clone、`PhiInst`、O1 cleanup。
- 前置依赖：O1、B2；E2 可降低代码膨胀风险。
- 预期收益：2%-8%，重点 `crypto/h-4/huffman` 等 helper-heavy 用例。
- 风险点：代码膨胀、递归误内联、return 合流和 phi 修补复杂。
- 功能测试：多块 if-return helper、纯函数、多调用点、递归负例、void/side-effect 负例。
- 性能测试：2026 perf，记录代码尺寸、编译耗时和 helper-heavy 热点变化。
- 建议执行顺序：B2 后做小阈值版本，再逐步扩大。
- 是否建议实现：建议。

### B3 SCCP 稀疏条件常量传播

- 优先级：P1。
- 当前项目状态：常量传播主要靠 `ConstantFoldPass` 的局部折叠；perf3 SCCP 第一版功能正确但性能不升，未提交。
- hy 参考：hy 主线更依赖 `RegularFold/SimplifyCFG/AggressiveDCE`，没有直接同名 SCCP 主线；可借鉴其 cleanup 组合方式。
- 当前问题：当前无法通过 executable edge 删除不可达 incoming 和不可达边；inline 后常量实参也难以跨 CFG 收敛。
- 优化目标：实现 `undef/const/overdef` lattice，按 executable edge 传播 phi 和分支；替换确定常量后交给 O1/B2 cleanup。
- 实现思路：不单独追求 SCCP 首轮收益；必须和 O1 cleanup 组合，且只替换确定常量，不做 risky range。
- 涉及模块：新增 `SCCPPass`、`SimplifyCFGPass`、`TrivialPhiPass`。
- 前置依赖：O1、B2。
- 预期收益：1%-6%，对常量开关、inline 后 helper、递归边界判断有帮助。
- 风险点：phi incoming 只应看 executable predecessor；不可达边删除要同步 CFG/phi。
- 功能测试：常量分支、循环 phi、不可达 incoming、overdefined 负例。
- 性能测试：2026 perf，收益小则复跑。
- 建议执行顺序：B2/F1 后重做。
- 是否建议实现：建议但不是第一批。

### A2 InlineStore / 跨块 store-to-load forwarding

- 优先级：P1。
- 当前项目状态：已有 `LocalStoreForwardPass` 和 `DLEPass`，但 LocalStoreForward 只在同一基本块 exact pointer 上前递，DLE 遇到 call/unknown alias 会清空。
- hy 参考：`Testing/Hycompiler/src/opt/InlineStore.cpp`、`Testing/Hycompiler/src/opt/DLE.cpp`、`Testing/Hycompiler/src/opt/DSE.cpp`。
- 当前问题：一些 load 的最近 store 支配 load，且中间无 clobber，但当前局部 pass 无法跨块前递。
- 优化目标：用支配树 + MemoryAlias 追踪最近 store，在 exact/base+offset 且无 may-alias store/call 时替换 load。
- 实现思路：先只处理同一函数内、非循环或 C2 已规范循环中的 exact location；未知 call 和指针形参全部保守 clobber。
- 涉及模块：`MemoryAlias`、`DLEPass`、`IRCFG`、`StoreInst`、`LoadInst`。
- 前置依赖：O1、B2；若和 A1 组合，依赖 C2/D1。
- 预期收益：1%-5%，偏向数组局部临时和参数槽。
- 风险点：alias/clobber 判断错误会直接错编；perf4 unknown-offset 精确化已有段错教训。
- 功能测试：跨块 store-load、if 合流、call clobber、may alias 负例。
- 性能测试：2026 perf，重点 `many_mat_cal/sl/transpose`。
- 建议执行顺序：B2 后作为内存 cleanup 子阶段做。
- 是否建议实现：谨慎建议。

### D2 小常数循环展开 + 展开后 cleanup

- 优先级：P1。
- 当前项目状态：缺失；perf2 的 SCEV/unroll 候选功能通过但 timer 明显回退，perf5 因依赖未满足暂缓。
- hy 参考：`Testing/Hycompiler/src/opt/LoopUnroll.cpp`、`Testing/Hycompiler/src/opt/SCEV.cpp`。
- 当前问题：固定 kernel、小 trip count 循环仍有分支和归纳变量成本，但无成本模型展开会导致代码膨胀和寄存器压力。
- 优化目标：只展开固定小 trip count、低 body cost、低 phi 数、无复杂 call/store 的循环；展开后立刻跑 O1/B2 cleanup。
- 实现思路：只支持 trip count <= 4/8 的单块或小块循环；设置 IR 指令增长上限；对历史回退 case 建成本规则。
- 涉及模块：`LoopAnalysis`、C2、`PhiInst`、`BasicBlock` clone。
- 前置依赖：C2、D1、B2、E2。
- 预期收益：2%-8%，命中固定 kernel 时更高。
- 风险点：代码膨胀、live range 增长、I-cache 和 RA 回退。
- 功能测试：固定 0/1/2/4 次循环、嵌套小循环、phi 多 incoming。
- 性能测试：2026 perf；收益接近噪声时至少复跑一次。
- 建议执行顺序：D1/E2 后再做最窄模式。
- 是否建议实现：建议但必须晚于 P0 主线。

### R3 TailCallOpt 扩展形态

- 优先级：P2。
- 当前项目状态：`TailCallOptPass` 已处理 `ret (call self(args))` 并在 perf5 保留，`h-1-*` 已明显下降。
- hy 参考：`Testing/Hycompiler/src/pre-opt/TCO.cpp`。
- 当前问题：剩余热点已不再以递归为主；继续扩展 TCO 的收益不如循环地址和内存优化。
- 优化目标：支持更多直接尾递归形态，如尾调用前有纯 cast/copy，或多个 tail return block。
- 实现思路：只在有新递归热点时做；仍禁止非 self call、非 tail call 和参数被复杂 phi 使用的场景。
- 涉及模块：`TailCallOptPass`、`CallInst`、`ReturnInst`、`PhiInst`。
- 前置依赖：无强依赖。
- 预期收益：0%-2%。
- 风险点：误判非 tail call 会错；入口已有 phi 的情况仍复杂。
- 功能测试：多返回尾递归、非尾递归负例、参数更新顺序。
- 性能测试：重点观察 `h-1-*` 是否还有下降。
- 建议执行顺序：P2，可等出现新热点再做。
- 是否建议实现：暂不优先。

## 7. 建议执行顺序

建议主线：

```text
O1. 可观测 O2 pipeline 与 cleanup 门控
  -> B2. 完整 GVN + 更窄 ADCE cleanup
  -> C2. 按需 LoopSimplify / 目标循环 LCSSA/Rotate
  -> D1. SCEV 地址递推 / loop strength reduction
  -> E2. 后端压力统计 + 白名单机器 cleanup/remat
  -> A1. 循环内存标量替换
  -> F1. Late inline + inline 后二次优化
  -> D2. 小常数循环展开
  -> B3/A2/R3/A3 按热点复查插入
```

排序理由：

- O1 先做，是为了避免继续出现“功能正确但性能负向、原因不可观测”的局面。
- B2 是 D1/F1/D2 的标量 cleanup 基础，且 B2a 已证明该方向有稳定小收益。
- C2 必须吸收 perf5 C1b 的失败教训，按需修补目标循环，而不是全局 LCSSA。
- D1 直接命中当前最大热点组，是本轮最核心的性能候选。
- E2 不再裸上机器 DCE/offset combine，而是先统计、再白名单，用于承接 D1/A1/D2。
- A1 和 D2 都会增加 phi/live range，必须等 C2/B2/D1/E2 更稳。
- F1 需要 B2/O1 承接 inline 后 IR 膨胀，适合作为 P1 中段。

## 9. 暂时不建议做的优化

| 优化 | 暂不建议原因 | 后续条件 |
| --- | --- | --- |
| 全函数通用 LCSSA | perf5 C1b 功能正确但 `crypto-1/crypto-2` perf timeout | 仅按 D1/A1 候选循环做按需 LCSSA |

| 无成本模型 SCEV/unroll | perf2 曾功能过但性能大幅回退；perf5 D1/D2 因依赖未满足暂缓 | O1/B2/C2/E2 稳定后再做 |
| 泛化 GCM 全局代码移动 | 历史 GCM 子集功能过但 timer 明显回退，live range 拉长 | B2/C2/E2 完成并有压力模型后再小范围重试 |

| 继续堆 helper 采样特判 | perf3 已做多项 helper equivalence；继续加特判脆弱且泛化差 | 只有明确单点热点且安全证明强时才做 |
| 大范围 signed div/rem magic 降强 | hy 有实现，但 signed 语义、溢出和 RISC-V 验证风险高 | E2 后半逐条规则验证 |
| 结构化 `RaiseToFor/ColumnMajor/Fusion/Parallelize` | hy 依赖结构化 IR；当前项目已是 BasicBlock IR，照搬成本极高 | 除非后续重构前端/IR，不作为短期目标 |
| RV vectorize / parallelize | 当前 RV 后端无 SIMD，运行时并行支持也不是主线 | 暂不做 |
| 完整跨函数 alias / interprocedural memory opts | 实现复杂、错编风险高，当前热点更偏循环地址和局部内存 | A1/B2/D1 后再评估 |
