## 5. 详细优化方案

### O1a IR pass manager 可观测统计 + cleanup 门控入口

- 优先级：P0。
- 当前项目状态：`IRPassManager` 只顺序执行 pass，`run` 只表达成功/失败；pass 不暴露 changed/stats；当前无法判断某个 pass 是否真的改变 IR、改变多少基本块/指令，也无法做安全 fixpoint。
- hy 参考：`hy` 的 `Pass` 暴露 `stats()`，`PassManager` 在 `opts.stats` 下输出每个 pass 统计。
- 当前问题：perf5 的固定 cleanup/ADCE 功能正确但性能不稳定；缺乏 IR 规模统计和门控，难以判断大优化是否真正减少 IR 或只是增加压力。
- 优化目标：给当前 `IRPassManager` 增加 module 级统计、每个 pass 前后记录和默认关闭的统计输出；同时提供未来 cleanup pipeline 可复用的“运行到 IR 规模稳定或达到轮次上限”的入口。
- 实现思路：统计函数数、基本块数、指令数、terminator 数和带结果值指令数；manager 在每个 pass 前后采样并保存记录；通过环境变量控制是否打印，不改变默认输出和优化顺序；新增 `runUntilStable` 作为后续 cleanup 门控入口，但本阶段不在 `main.cpp` 启用。
- 涉及模块：`src/ir/passes/IRPassManager.h`、`src/ir/passes/IRPassManager.cpp`，必要时只更新文档。
- 前置依赖：无。
- 预期收益：单独直接收益接近 0；主要收益是为 B2c/C2a/D1a 提供统计证据和 cleanup 门控基础。
- 实现难度：中。
- 风险点：统计代码不能改变 IR；可选输出不能污染正常测试；`runUntilStable` 不能被误用成无限循环。
- 功能测试方式：构建；官方 ASM `compiler2026-riscv-function`；可选 IR 回归。
- 性能测试方式：同环境 baseline 与 O1a 之后 2026 perf，确认默认行为无明显退化。
- 是否建议本轮实现：建议优先实现。
- 当前状态：已完成并保留。

### B2c phi value numbering + 窄 ADCE cleanup

- 优先级：P0。
- 当前项目状态：B2b 已覆盖常量、binary、icmp/fcmp、zext、cast、GEP 的 value-numbered CSE；尚未处理 phi value numbering、纯 call、load GVN 或 ADCE。
- hy 参考：`GVN.cpp` 和 `AggressiveDCE.cpp`。
- 当前问题：后续 D1/F1 会产生等价 phi、死 phi 环和重复表达式，普通 DCE 不足以清理。
- 优化目标：先补 trivial/acyclic phi value number；再做只删除纯指令子图、不主动改 terminator 的窄 ADCE。
- 涉及模块：`LocalCSEPass` 或新增 `ADCEPass`、`TrivialPhiPass`、`DCEPass`。
- 当前状态：未开始。

### C2a 按需 LoopSimplify 形态检查与候选筛选

- 优先级：P0。
- 当前项目状态：已有 preheader + dedicated exit 子集；全局 LCSSA 已因 `crypto-*` timeout 撤回。
- hy 参考：`CanonicalizeLoop.cpp`、`LoopRotate.cpp`。
- 优化目标：不重做全局 LCSSA，而是为 D1/A1 候选循环建立形态检查、缺口报告和小范围修补入口。
- 当前状态：未开始。

### D1a SCEV row-base/address strength reduction 第一版

- 优先级：P0。
- 当前项目状态：缺通用 SCEV；最大热点仍偏矩阵、stencil、transpose 地址计算。
- hy 参考：`SCEV.cpp`、`LoopUnroll.cpp`、RV `StrengthReduct.cpp`。
- 优化目标：优先处理单 latch、常量 step、低风险 GEP row-base 外提或地址递推。
- 当前状态：未开始。
