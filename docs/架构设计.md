# 架构设计

本文档描述当前源码实现，而不是完整 MiniC 目标形态。更细的逐文件说明见 [Architecture 文档导航](./Architecture/README.md)。

## 1. 总体流水线

项目采用三段式编译流程：

```text
frontend -> ir -> backend
```

真实数据流如下：

```text
source(.c)
  -> ASTGenerator
  -> ANTLR4 Lexer/Parser
  -> CSTVisitor
  -> ast_node 树
  -> IRGenerator
  -> Module / Function / Instruction / Value
  -> BackendDriver
  -> IRAdapter
  -> FrameLayoutBuilder
  -> InstructionSelector
  -> AsmPrinter
  -> RISC-V64 assembly(.s)
```

主控逻辑在 `src/main.cpp` 的 `compile()`：

1. `ArgsAnalysis` 解析命令行参数。
2. `ASTGenerator` 生成 AST。
3. 如果指定 `-T`，通过 `OutputAST` 输出 AST 图片后结束。
4. `Module` 保存函数、变量、常量、作用域等模块级上下文。
5. `IRGenerator` 把 AST 翻译成线性 IR。
6. 如果指定 `-I`/`-L`，`Module::outputIR` 输出 LLVM 风格文本 IR 后结束。
7. 默认进入 `BackendDriver`，输出 RISC-V64 汇编。

## 2. 当前语言能力边界

当前支持 MiniC 子集的大部分功能，覆盖整数和浮点标量、数组、控制流和基础优化：

- 类型：`int`、`float`、`void`、数组（一维和多维）、指针（函数参数数组退化）
- 变量：全局/局部变量、全局/局部 `const` 常量、`static` 存储类（静态局部变量、静态全局变量、静态函数，内部链接）
- 数组：一维和多维数组声明、下标访问、初始化列表、零初始化、全局数组和局部数组
- 函数：定义、标量形参（前 8 个走 `a0-a7`，超出部分走栈）、调用、返回值
- 语句：声明、赋值、块语句、表达式语句、`return`、`if` / `if-else`、`while`、`for`（含头声明和逗号步进）、`break`、`continue`
- 表达式：整数常量、浮点常量、变量引用、函数调用、`+ - * / %`、`< <= > >= == !=`、`! && ||`（短路求值）、一元 `+ -`、前缀/后缀 `++ --`
- 内置函数：`putint`、`getint`、`putfloat`、`getfloat`、`putch`、`getch`、`getarray`、`putarray`、`getfarray`、`putfarray`
- 语义诊断：重复定义、未定义变量/函数、参数数量和类型不匹配、全局初始化限制、常量赋值检查（E1303）、常量未初始化（E1304）
- 优化管线（`-O1`）：Verify → SimplifyCFG → Mem2Reg → ConstantFold → TrivialPhi → DCE，全部 250 个 IR 测试通过

近期修复：

- 局部变量声明初始化会先按外层作用域求值，再把新变量绑定到当前作用域，避免 `int x = x + 1;` 这类隐藏变量场景误读新槽位。
- 后端 `.data` 段全局聚合初始化会只提取标量元素，不再把 LLVM 聚合类型里的维度数字误当成数组元素，覆盖多维全局数组和 `const` 数组初始化。

暂未完整支持或存在已知问题：

- 后端浮点指令选择：IR 层 `float` 已完整支持，但 ASM 后端尚未接入浮点 load/store/算术指令
- 寄存器分配：当前使用 naive 分配器（`vreg % 5 -> t0..t4`），非图着色
- phi lowering：基础场景已通过，critical edge、循环 phi、多 phi 并行 copy 等边界场景需继续压测
- 不支持：`struct`、`enum`、`typedef`、字符串/字符数组

## 3. Frontend

前端负责把源码文本变成自定义 AST。

关键文件：

- `src/frontend/antlr4/MiniC.g4`：当前 MiniC 子集的词法和语法定义。
- `src/frontend/ASTGenerator.cpp`：ANTLR4 入口，负责读取文件、构造 lexer/parser、触发 CST visitor。
- `src/frontend/CSTVisitor.cpp`：把 ANTLR CST 转成项目自定义 AST。
- `src/frontend/include/AST.h`：AST 节点类型、节点字段和工厂函数。
- `src/frontend/Graph.cpp`：用 Graphviz 输出 AST 图片。

当前 AST 节点不仅保存语法结构，也带有中端翻译会复用的字段：

- `blockInsts`：该节点翻译出的 IR 指令片段。
- `val`：该节点表达式求值后的 `Value`。
- `needScope`：控制 block 翻译时是否自动进出作用域。

## 4. IR

IR 层是当前项目的中枢，负责两件事：

1. 把 AST 翻译成线性指令序列。
2. 管理符号、作用域、类型和值之间的依赖关系。

关键文件：

- `src/ir/IRGenerator.cpp`：AST 到 IR 的核心翻译器。
- `src/ir/include/Module.h`、`src/ir/Module.cpp`：模块级容器，管理函数、全局变量、常量池和作用域。
- `src/ir/include/Function.h`：函数对象，持有形参、局部变量和 `InterCode`。
- `src/ir/include/Instruction.h`：IR 指令基类与操作码。
- `src/ir/include/Value.h`、`User.h`、`Use.h`：值系统与 def-use 关系。
- `src/symboltable/ScopeStack.*`：变量作用域栈。

当前接通的 IR 指令包括：

- 内存操作：`alloca`、`load`、`store`、`getelementptr`
- 整数运算：`add`、`sub`、`mul`、`sdiv`、`srem`
- 浮点运算：`fadd`、`fsub`、`fmul`、`fdiv`
- 比较：`icmp`、`fcmp`
- 类型转换：`zext`、`sitofp`、`fptosi`
- 控制流：`br`（条件/无条件）、`ret`
- 函数调用：`call`
- SSA：`phi`
- 聚合：`zeroinitializer`

链接属性：`GlobalValue` 支持 `ExternalLinkage`（默认）和 `InternalLinkage`（`static`），后端据此决定是否发射 `.globl` 指令。

优化 passes 已接入：`VerifyPass`、`SimplifyCFGPass`、`Mem2RegPass`、`ConstantFoldPass`、`TrivialPhiPass`、`DCEPass`。CFG 分析基础设施（支配树、支配边界）已实现在 `IRCFG` 中。

## 5. Backend

后端目标是输出 RISC-V64 汇编。它不再使用旧的 `backend/riscv64` 目录结构，当前实现集中在 `src/backend`。

关键文件：

- `src/backend/include/BackendDriver.h`、`src/backend/BackendDriver.cpp`：后端总入口，负责全局变量发射和函数编译流水线。
- `src/backend/include/IRAdapter.h`、`src/backend/IRAdapter.cpp`：为后端提供 `Module/Function/Instruction/Value` 的只读视图。
- `src/backend/include/FrameLayout.h`、`src/backend/FrameLayout.cpp`：计算函数栈帧布局。
- `src/backend/include/InstructionSelector.h`、`src/backend/InstructionSelector.cpp`：把 IR 指令翻译成 Machine IR（虚拟寄存器指令）。
- `src/backend/include/MachineIR.h`、`src/backend/MachineIR.cpp`：机器级 IR，含虚拟/物理寄存器、MachineInstr、MachineBasicBlock、MachineFunction。
- `src/backend/include/MachineCFG.h`、`src/backend/MachineCFG.cpp`：Machine IR 上的 CFG 构建。
- `src/backend/include/MachineLiveness.h`、`src/backend/MachineLiveness.cpp`：Machine IR 上的活跃性分析。
- `src/backend/include/NaiveRegisterAllocator.h`、`src/backend/NaiveRegisterAllocator.cpp`：朴素寄存器分配（`vreg % 5 -> t0..t4`）。
- `src/backend/include/MachineAsmLowering.h`、`src/backend/MachineAsmLowering.cpp`：Machine IR 到 AsmFunction 的降低。
- `src/backend/include/Asm.h`、`src/backend/Asm.cpp`：结构化汇编对象与最终文本打印。

后端当前链路（两层架构）：

```text
Module
  -> IRAdapter::adapt -> IRModuleView
  -> BackendDriver 遍历全局变量和函数
     -> FrameLayoutBuilder::build
     -> InstructionSelector::run      (IR -> MachineFunction)
     -> MachineCFGBuilder::run        (构建 Machine CFG)
     -> NaiveRegisterAllocator::run   (虚拟寄存器 -> 物理寄存器)
     -> MachineAsmLowering::run       (MachineFunction -> AsmFunction)
     -> AsmPrinter::printFunction     (输出 RISC-V64 汇编)
```

当前策略：

- 局部变量、形参和 IR 临时结果统一分配栈槽。
- 栈槽最小 8 字节，函数栈帧按 16 字节对齐。
- 参数寄存器使用 `a0-a7`，返回值使用 `a0`。
- 指令选择生成虚拟寄存器，经 naive 分配器映射到 `t0-t4`。
- 暂无图着色寄存器分配器，暂无 peephole 优化。

## 6. 测试与迭代节奏

当前基线测试由 `scripts/ci_test_plan.txt` 控制：

```sh
bash scripts/run_ci_tests.sh --all --compiler ./build/compiler
```

建议后续按“一个语言能力 + 一小批测试”的节奏迭代：

1. 修改 `MiniC.g4` 扩语法。
2. 修改 `CSTVisitor.cpp` 和 `AST.h` 扩 AST。
3. 修改 `IRGenerator.cpp` 和必要的 IR 指令/Value/Type。
4. 修改 `InstructionSelector.cpp` 和必要的后端布局逻辑。
5. 在 `scripts/ci_test_plan.txt` 解锁对应测试。
6. 跑 `--all` 确认旧能力没有回归。
