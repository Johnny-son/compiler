# 性能优化2：按依赖链推进的优化计划

本文档用于接替 `性能优化.md` 的流水式记录，把后续优化改成按依赖关系推进的路线图。核心原则是：先补共同前置分析，再做依赖它们的收益型优化；每完成一个关键优化点，都必须用功能测试和性能测试证明有效后再提交。

## 总体分层

后续优化分为四个大点。

| 大点 | 目标 | 依赖 | 产出 |
| --- | --- | --- | --- |
| A. 内存分析与内存优化 | 理解地址来源，删除冗余 load/store | `Mem2Reg` 后的 SSA 和 CFG | `Alias/Base`、`DLE`、`DSE`，并为 LICM 提供安全性依据 |
| B. 循环结构基础设施 | 让循环形态可分析、可变换 | CFG、支配关系、内存优化后的简化 IR | `LoopInfo`、preheader、latch、exit、`CanonicalizeLoop` |
| C. 循环强优化 | 针对热点循环减少迭代内计算 | A、B | SCEV 归纳变量、线性地址递推、小常数循环展开 |
| D. 全局移动与清理 | 清理 C 阶段产生的冗余，把计算放到更合适位置 | B 的 loop depth 和支配树 | 更完整 GVN、GCM、后续 cleanup |

## 顺序逻辑

```text
当前 O1
  -> A1 Alias/Base
  -> A2 DLE
  -> A3 DSE
  -> A4 LICM 使用 alias 扩大安全外提范围
  -> B1 LoopInfo
  -> B2 CanonicalizeLoop
  -> C1 SCEV
  -> C2 ConstLoopUnroll
  -> D1 GCM
  -> D2 cleanup round: Fold + GVN/CSE + DCE
```

为什么这个顺序不能颠倒：

- 没有 Alias/Base，DLE/DSE 只能做 exact pointer，无法判断 `gep a, i` 和 `gep b, i` 是否一定不别名。
- 没有 DLE/DSE，LICM 即使找到不变量 load/store，也无法安全证明循环内是否有覆盖写。
- 没有 LoopInfo/CanonicalizeLoop，SCEV 和 unroll 没有稳定的 header、latch、preheader、exit 结构。
- 没有 SCEV，unroll 只能处理极少数常量条件，无法理解归纳变量和 trip count。
- 没有 loop depth，GCM 不能判断“尽量移出循环”和“尽量下沉到分支”的成本。

## 阶段计划

### A. 内存分析与内存优化

| 阶段 | 子点 | 实现思路 | 验收预期 |
| --- | --- | --- | --- |
| A1 | Alias/Base | 为 `alloca`、`global`、`gep` 建立保守地址描述：base + 常量 offset 或 unknown offset；先不跨函数传播 | 本身可不单独提分，但要作为 DLE/DSE 的共同前置 |
| A2 | DLE | 删除冗余 load；同一地址在无别名写和无 impure call 之间重复读取时复用旧值；store 后 load 同址时前递 store value | 预期 timer 改善 0.5%-3%，重点看矩阵、transpose、conv2d |
| A3 | DSE | 删除被同址后续 store 覆盖、且中间无可能读取的旧 store；只处理未逃逸 local alloca 或可证明安全地址 | 预期 timer 改善 0.5%-3%，不得影响功能正确性 |
| A4 | LICM-alias | 让 LICM 用 alias 判断循环内是否存在可能写，扩大只读 load 和地址计算外提范围 | 预期在循环热点上再改善 1%-5% |

### B. 循环结构基础设施

| 阶段 | 子点 | 实现思路 | 验收预期 |
| --- | --- | --- | --- |
| B1 | LoopInfo | 基于支配关系识别 backedge、header、latch、loop body、exit；形成循环森林 | 作为后续共同前置，先通过 verifier 和功能测试 |
| B2 | CanonicalizeLoop | 为简单循环补 preheader，统一单 latch/单 exit 能力；暂不强制复杂 LCSSA | 让 LICM/SCEV/unroll 可依赖稳定结构 |

### C. 循环强优化

| 阶段 | 子点 | 实现思路 | 验收预期 |
| --- | --- | --- | --- |
| C1 | SCEV | 识别 `i = phi(start, i + step)`、比较退出条件和 trip count；先支持 int32 常量 step | 预期热点循环 2%-8% 改善 |
| C2 | 线性地址递推 | 把循环内重复 `gep base, i` 的乘加地址计算改成递增指针或复用递推值 | 重点改善 `conv2d-*`、`matmul*`、`transpose*` |
| C3 | ConstLoopUnroll | 对小常数 trip count 循环展开，设置代码尺寸上限，展开后跑 Fold/CSE/DCE | 预期小循环和固定轮次 case 有正收益 |

### D. 全局移动与清理

| 阶段 | 子点 | 实现思路 | 验收预期 |
| --- | --- | --- | --- |
| D1 | GCM | 基于支配树和 loop depth 做 schedule early/late；纯计算尽量外提或下沉 | 依赖 LoopInfo，目标 1%-5% |
| D2 | Cleanup round | 每个大优化后固定跑 `ConstantFold -> LocalCSE/GVN -> DCE -> SimplifyCFG` | 稳定吸收优化产物，防止 IR 膨胀 |

## 当前进行中：A1-A2-A3

实现边界：

- 地址描述只包含三种状态：
  - `known(base, offset)`：base 为 `alloca`、`global`、指针形参或可追踪 GEP 的根；offset 是常量字节偏移。
  - `known(base, unknown offset)`：base 已知但偏移不确定。
  - `unknown`：无法证明别名关系。
- `mustAlias` 只在 base 相同且 offset 都确定相等时成立；exact pointer 相同也视作 must alias。
- `neverAlias` 只在 base 都已知且 base 不同时成立；其他情况保守为 may alias。
- DLE 先做同块和简单数据流可用 load/store；遇到 call 时清空内存可用信息。
- DSE 先做同块 dead store：`store a, p` 后到下一个同址 `store b, p` 前没有可能读/写/调用，则删除前一个 store。

风险控制：

- 不删除全局 store，除非后续能证明全局未读。
- 不跨函数传播 alias，避免误判指针参数。
- 不对 unknown offset 做 aggressive 删除。
- 每次删除 store/load 都先更新 def-use，再删除指令对象。

## A1-A2-A3 实测记录

实现内容：

- 新增 `MemoryAliasAnalysis`，对 `alloca`、`global`、指针形参和 `gep` 建立保守的 base/offset 描述。
- 新增 `DLEPass`，用 available memory dataflow 删除冗余 load，并复用 store 后的同址值。
- 新增 `DSEPass`，删除同块被覆盖 store、同值冗余 store，并对未逃逸局部数组做 backward DSE。
- 在 O1 管线中分别于前半轮和 LICM 后运行 `DLE -> DSE`。
