当前优化范围：

- 做：IR 到后端前的优化，包括 CFG 清理、常量折叠、代数化简、DCE、循环相关优化。

本轮和 Hycompiler 再次对比后的差距：

- Hycompiler 有 `GVN.cpp` 和 `GCM.cpp`，能跨基本块复用纯表达式并把计算移动到更合适的位置；本项目此前只有局部常量折叠、DCE 和 LICM，缺少 CSE/GVN。
- Hycompiler 的循环链路包括 `CanonicalizeLoop.cpp`、`LoopRotate.cpp`、`LoopUnroll.cpp`、`SCEV.cpp`，本项目目前只有保守 LICM，还没有循环规范化、旋转、展开和归纳变量分析。
- Hycompiler 有 `RangeAwareFold.cpp`、`AggressiveDCE.cpp`、`InlineStore.cpp` 等细化优化；本项目后续优先选择 IR 到后端前、风险可控、容易用 2026 性能集验证的子集。
- 本阶段先实现单基本块 Local CSE，作为 GVN/GCM 前置切片；后续再做循环规范化和小循环展开，不考虑多面体和 peephole。

## 记录规则

- 每个优化 commit 都新增一行性能记录。
- 每次记录必须写清楚测试命令、测试集、正确性结果和性能指标。
- 性能数字优先记录运行时表现；必要时补充生成汇编大小、编译耗时和超时数量。
- 不自动运行会改文件的格式化工具，例如 `rustfmt`。

建议记录字段：

- `阶段`：优化阶段名。
- `commit`：对应提交哈希；提交前可写 `未提交`。
- `优化内容`：本阶段实际做了什么。
- `测试命令`：用于复现实测数据的命令。
- `正确性`：功能测试是否通过。
- `性能指标`：总耗时、几何平均加速比、通过数、超时数等。
- `相对变化`：相对上一阶段或基线的变化。
- `备注`：风险、未覆盖场景、需要复测的点。

计分标准：

- `timer_ms`：运行库在 `-DOPT_TEST` 下输出的 `TOTAL` 或 `Timer@` 累加时间，主要衡量程序核心计算区，越低越好。

## 阶段 1 实测：常量折叠和 GEP scale 强度削弱

实现内容：

- `ConstantFoldPass` 增加整数恒等式：`x + 0`、`x - 0`、`x - x`、`x * 0`、`x * 1`、`x / 1`、`x % 1` 等。

## 阶段 2 实测：后端立即数和 zero 寄存器选择

实现内容：

- 新增 `MachineOpcode::ADDIW`，汇编输出为 `addiw`。
- 整数 `add/sub` 在 lowering 阶段遇到 12-bit 有符号小立即数时，直接生成 `addiw`，避免 `li` 临时寄存器加 `addw/subw`。
- 整数比较遇到常量 0 时直接使用 RISC-V `zero` 物理寄存器，避免额外 `li 0`。
- 该优化发生在 IR 到 MachineIR 的指令选择阶段，不扫描已经生成的机器码，因此不属于 peephole。

## 阶段 3 实测：比较分支融合

实现内容：

- 新增 `MachineOpcode::BEQ/BNE/BLT/BGE`，补齐汇编输出和 MachineCFG 目标边识别。
- 如果 `ICmpInst` 的结果只被条件分支使用，则跳过该 `icmp` 的普通 bool 结果生成。
- `translateBranch` 直接查看条件操作数背后的 `ICmpInst`，把 `eq/ne/slt/sgt/sle/sge` 映射到 RISC-V 条件分支。
- 常量 0 继续直接使用 `zero` 寄存器，减少 `li 0`。

安全边界：

- 只融合整数比较；浮点比较仍保留原有 `fcmp -> bool -> bnez` 路径。
- 只有当 `icmp` 的 use 全部是条件分支时才跳过 bool 结果生成；如果还被其他指令使用，仍生成原结果。
- true edge 仍然复用原有 phi-copy 处理逻辑，false edge 仍作为条件分支后的 fall-through 路径处理。

- 不可达块删除。
- 保守空跳转块旁路。

## 接下来优化计划

### 阶段 1：增强 ConstantFoldPass（已完成）

目标：

- 在现有纯常量折叠基础上补充安全代数化简。
- 优先清理循环体里的恒等计算，减少后端指令数和寄存器压力。

实现思路：

1. 参考 Hycompiler `RegularFold.cpp`，只选不改变语义的规则。
2. 对整数：
   - `x + 0 -> x`
   - `0 + x -> x`
   - `x - 0 -> x`
   - `x - x -> 0`
   - `x * 1 -> x`
   - `1 * x -> x`
   - `x * 0 -> 0`
   - `0 * x -> 0`
   - `x / 1 -> x`
   - `x % 1 -> 0`
3. 对同值整数比较：
   - `x == x -> true`
   - `x != x -> false`
   - `x < x -> false`
   - `x <= x -> true`
   - `x > x -> false`
   - `x >= x -> true`
4. 对后端 GEP scale：
   - `scale == 1` 时跳过 scale 计算。
   - `scale` 是 2 的幂时生成 `slli`。
   - 其他 scale 保持 `li + mul`。
5. 每次替换后维护 use-def 链，再交给 DCE 清理旧指令。

安全边界：

- 不做可能影响除零、溢出、NaN 或有符号右移语义的规则。
- 暂不做重关联和分配律。
- 暂不跨基本块做 CSE/GVN。

预期收益：

- 实测对总分改善 3.21%，达到预期下界。
- 第一版只做整数和 GEP scale；浮点恒等式继续暂缓。

### 阶段 2：后端立即数和 zero 寄存器选择（已完成）

目标：

- 降低常见整数表达式 lowering 后的 `li + addw/subw` 指令数。
- 减少比较 0 时的临时寄存器物化。
- 不做后端 peephole，只在 IR 到 MachineIR 的选择阶段直接生成更合适的 RISC-V 指令。

实现思路：

1. 新增 `MachineOpcode::ADDIW` 并补齐 MachineIR/汇编输出。
2. `add x, imm12`、`add imm12, x` 直接生成 `addiw`。
3. `sub x, imm12` 在 `-imm12` 仍为 12-bit 有符号立即数时生成 `addiw x, -imm12`。
4. `icmp` 中的常量 0 使用 `PhysicalReg::Zero`，避免 `li 0`。
5. 其他立即数保持原 lowering，避免引入新的合法化风险。

安全边界：

- 只处理 `i32` 的 `add/sub`，使用 `addiw` 保持 32-bit 结果截断和符号扩展语义。
- 只选择 12-bit signed immediate，超范围继续走原来的 `li + addw/subw`。
- 比较 0 使用 RISC-V 常量零寄存器，不改变比较谓词。

预期收益：

- 实测阶段内改善 3.65%，累计较当前 O1 改善 6.74%。
- 对 `knapsack_naive-*`、`transpose2`、`many_mat_cal-*` 和 `sl1/sl2` 收益明显。

### 暂缓项：完善 SimplifyCFGPass

已验证候选：

- 合并 `bb -> succ` 且 `succ` 只有一个前驱的基本块。
- 折叠 `br cond, X, X` 为无条件跳转。

实测结果：

- 完整单前驱后继内联：timer 总分 35009 ms，慢于阶段 1 的 34605 ms。
- 只保留同目标分支折叠：timer 总分 34952 ms，仍慢于阶段 1。

结论：

- 该方向能改善部分用例，但对 `knapsack_naive-3`、`many_mat_cal-2`、`shuffle1` 等产生更大回退，可能与后端块布局和寄存器压力相关。
- 当前不提交；后续如果实现块布局或更稳定的寄存器压力控制，再重新评估。

### 阶段 3：比较分支融合（已完成）

目标：

- 避免 `icmp` 只用于条件跳转时生成 bool 临时值并落栈。
- 直接把整数比较条件 lowering 成 RISC-V 条件分支。
- 保持 phi-copy 边处理和原 CFG 语义。

实现思路：

1. 新增 `BEQ/BNE/BLT/BGE` 机器指令并补齐 MachineCFG 目标识别。
2. 如果 `ICmpInst` 的所有 use 都是条件分支，则不生成普通 bool 结果。
3. 在 `translateBranch` 中直接读取条件背后的 `ICmpInst`。
4. 将 `eq/ne/slt/sgt/sle/sge` 映射到 `beq/bne/blt/bge`，必要时交换 lhs/rhs。
5. 比较常量 0 继续用 `zero` 寄存器。

安全边界：

- 只融合整数比较，不动浮点比较。
- `icmp` 被其他非分支指令使用时仍生成原 bool 值。
- 仍沿用原 true edge/false edge phi-copy 发射逻辑。

预期收益：

- 实测阶段内改善 2.53%，累计较当前 O1 改善 9.10%。
- 对矩阵、背包、排序、CRC 和部分循环类用例收益明显。

### 暂缓项：增强 DCE

已验证候选：

- 清理互相引用但没有外部使用的 phi 环。

实测结果：

- timer 总分 35975 ms，慢于阶段 2 的 33342 ms。

结论：

- 正确性通过，但对 `matmul2`、`shuffle1/2`、`sl1` 等热点产生显著回退。
- 当前不提交；后续如果先优化 phi lowering 或寄存器压力，再重新评估。

### 阶段 4：循环不变量外提 LICM（已完成）

目标：

- 对性能热点中的嵌套循环，外提与循环迭代无关的纯计算。
- 先做保守 LICM，不处理别名复杂的 load/store。

实现思路：

1. 增加最小 LoopInfo：识别回边、header、latch、loop body。
2. 尝试识别 preheader；没有 preheader 的循环先跳过。
3. 只外提纯指令：安全二元运算、比较、zext/cast、常量地址计算。
4. 如果指令所有操作数都定义在循环外或已经被标记为 invariant，则移动到 preheader terminator 前。
5. 不外提 load/store/call/terminator/phi。
6. 参考 Hycompiler `LICM.cpp` 的纯计算外提思路，但暂不采用其中的 load/store alias 处理。
7. 修正后端比较分支融合：只有 `icmp` 与条件分支在同一基本块时才直接融合；LICM 外提后的跨块条件先物化 bool，避免绕过 frame slot 生命周期分析。

安全边界：

- 不做 alias analysis，因此内存读写不动。
- 不处理没有单一 preheader 的循环。
- 不外提可能触发除零或浮点除法边界的 `sdiv/srem/fdiv`。
- 每移动一批后跑 `VerifyPass`。

### 阶段 5：小纯函数内联（已完成）

目标：

- 参考 Hycompiler 的 `EarlyInline.cpp`、`Inline.cpp`、`LateInline.cpp`，补齐本项目完全缺少内联的问题。
- 先只内联小规模纯计算 helper，暴露跨函数常量折叠、LICM 和后端指令选择机会。
- 避免第一版引入多块 CFG 拼接、return phi 合成、内存副作用和递归调用风险。

实现思路：

1. 新增 `InlineSimpleFunctionPass`，放在 `Mem2RegPass` 之后、`ConstantFoldPass` 之前。
2. 只接受非 builtin、非 void、单基本块、单返回值函数。
3. 只克隆纯指令：`BinaryInst`、`ICmpInst`、`FCmpInst`、`ZExtInst`、`CastInst`、`GetElementPtrInst`。
4. 限制可内联函数体最多 8 条纯计算指令，避免代码膨胀。
5. 实参映射到形参，克隆后的返回值替换 call 的所有 use，再删除 call。
6. 内联后继续运行 `VerifyPass`、`ConstantFoldPass`、`SimplifyCFGPass`、`TrivialPhiPass`、`LICMPass`、`DCEPass`。

安全边界：

- 不内联递归调用。
- 不内联含 `load/store/call/alloca/phi/branch` 的函数。
- 不内联 void 函数和多基本块函数。
- 不处理多返回路径，不合成返回值 phi。

### 阶段 6：全局 const 标量 load 折叠（已完成）

目标：

- 将只读全局 `const` 标量的 `load` 替换为常量立即数。

### 阶段 7：布尔规约驱动分支融合（已完成）

目标：

- 清理 IRGenerator 常见的 `icmp -> zext -> icmp ne 0 -> br` 布尔链。
- 让条件分支直接使用原始 `i1` 比较结果，从而触发阶段 3 的 compare-branch fusion。
- 减少 bool 临时值物化、栈槽读写和二次比较。

实现思路：

1. 在 `ConstantFoldPass` 中识别 `ICmpInst` 的操作数。
2. 对 `zext i1 x to i32 != 0` 直接替换为 `x`。
3. 对 `zext i1 x to i32 == 1` 直接替换为 `x`。
4. 暂不处理 `== 0` 或 `!= 1`，因为这需要构造逻辑取反或反转使用点。
5. 替换后由 DCE 删除多余 `zext`，由后端分支融合直接生成 `beq/bne/blt/bge`。

安全边界：

- 只处理源操作数类型为 `i1` 的 `zext`。
- 只处理等价于原值本身的比较，不创建取反。
- 不改变浮点比较和短路逻辑 CFG。

### 阶段 8：只读全局标量 load 外提（已完成）

目标：

- 在 LICM 中补充一个保守的内存类优化：外提循环内重复读取的全局标量。
- 重点覆盖 `N_eff`、`repeat_factor` 等在热点循环内只读的全局配置值。

实现思路：

1. 在 LICM 中允许 `LoadInst` 成为候选，但只接受 pointer operand 为 `GlobalVariable` 的标量 load。
2. 限制 load 结果类型为 `i32` 或 `float`，不处理数组和聚合。
3. 如果循环体内存在 `CallInst`，跳过，避免调用修改全局状态。
4. 如果当前函数内存在对同一全局变量的直接 `store`，跳过。
5. 其余依旧使用 LICM 的 operand invariant 检查和 preheader 移动逻辑。

安全边界：

- 不做 alias analysis，不外提数组元素 load。
- 不跨可能有副作用的 loop-call。
- 不处理函数内会写回同一全局标量的情况。

### 阶段 9：局部 CSE/GVN（已完成）

目标：

- 参考 Hycompiler `GVN.cpp`/`GCM.cpp`，补齐本项目缺少公共子表达式消除的问题。
- 第一版只做同一基本块内的纯表达式复用，减少热点循环体里的重复地址计算、重复比较和重复算术。
- 保持优化位于 IR 到后端前，不做多面体优化，也不做后端 peephole。

实现思路：

1. 新增 `LocalCSEPass`，按基本块维护 `key -> Instruction` 的 available 表。
2. 只为有结果值且无副作用的指令生成 key：`BinaryInst`、`ICmpInst`、`FCmpInst`、`ZExtInst`、`CastInst`、`GetElementPtrInst`。
3. key 使用 opcode、谓词、目标类型和 operand identity，暂不交换归一化 commutative operands，避免误合并。
4. 命中重复表达式时，将后出现的 instruction 的 uses 替换为先出现的 instruction，然后从基本块删除。
5. 在 `ConstantFoldPass` 后和 `LICMPass` 后各跑一次，前者吃掉前端/折叠暴露出的重复表达式，后者清理外提后仍在循环体内的重复计算。

安全边界：

- 不处理 `load/store/call/phi/alloca/terminator`，避免内存、副作用和 CFG 边界问题。
- 只在同一基本块内复用，不跨块做 dominance 推理；后续如果做全局 GVN，再补 DominatorTree 和 MemorySSA/alias 边界。
- `GetElementPtrInst` 只作为纯地址表达式复用，不改变实际 load/store 顺序。

### 阶段 10：支配树范围 CSE/GVN（已完成）

目标：

- 将阶段 9 的单基本块 Local CSE 扩展到 dominator tree 范围，继续参考 Hycompiler `GVN.cpp` 的纯表达式复用方向。
- 保守复用支配当前块的纯表达式，减少 if/loop 结构中跨块重复的 GEP、比较和算术。
- 仍然不处理内存表达式，不做全局代码移动，避免 alias 和 live range 过度扩张。

实现思路：

1. `LocalCSEPass` 构建 `IRCFG` 和 `DominanceInfo`，从 entry block 沿 dominator tree 深度优先遍历。
2. 每进入一个 block，继承祖先 block 中可用的纯表达式表；离开 block 时回滚本 block 新插入的 key。
3. 如果当前指令的 key 已由支配它的祖先或同块前序指令提供，则替换当前 uses 并删除当前指令。
4. 复用范围仍限制在 `BinaryInst`、`ICmpInst`、`FCmpInst`、`ZExtInst`、`CastInst`、`GetElementPtrInst`。
5. 遇到 `load/store/call/phi/alloca/terminator` 直接跳过，不把内存和 CFG 语义纳入 CSE。

安全边界：

- 只沿支配树继承 available 表，因此不会把只在某个分支中计算的值复用到未被该分支支配的 merge block。
- 不跨函数、不跨内存操作做值编号。
- 当前版本可能延长少量值的 live range，所以用三次性能复测确认收益稳定性；中位数作为提交口径。

### 阶段 11：单 store alloca 前递（已完成）

目标：

- IR 检查发现函数参数指针会先存入 `%*.addr` 栈槽，再在热点循环里反复 `load` 回来；现有 `Mem2RegPass` 只提升 int/float alloca，没有处理 pointer alloca。
- 参考 Hycompiler `InlineStore.cpp` 的 store 前递思路，先做本项目更保守的局部栈槽前递。
- 减少矩阵类函数中的重复 pointer load，并让后续 CSE/GEP 复用更容易命中。

实现思路：

1. 新增 `SingleStoreAllocaPass`，放在 `Mem2RegPass` 之后。
2. 收集只被 `load` 和 `store` 使用的 `AllocaInst`，要求恰好一个 `store`，并且该 `store` 的 pointer operand 是这个 alloca。
3. 使用 `IRCFG` 和 `DominanceInfo` 确认唯一 store 支配所有 load；如果 store/load 在同一个基本块，还要求 store 出现在 load 之前。
4. 将所有 load 的 uses 替换为 store value，然后删除 load、store 和 alloca。
5. 不处理多 store、地址逃逸、store value 为 alloca 自身、未被唯一 store 支配的 load。

安全边界：

- 不引入 pointer 类型的默认零值，不扩展通用 Mem2Reg；只处理“已初始化且唯一 store 支配所有 load”的情况。
- 不处理数组元素 load/store，也不跨内存别名推理。
- 如果 alloca 作为普通值传递或被复杂指令使用，直接跳过。

### 阶段 12：局部 store-to-load 前递（已完成）

目标：

- 参考 Hycompiler `InlineStore.cpp` 的 store 前递方向，补一个比全局 alias/store 分析更保守的 IR 内存优化。
- 在同一基本块内识别 `store v, p` 后、没有任何 `store/call` 屏障时的 `load p`，把 load 的 uses 替换为 `v`。
- 重点减少循环体中由前端临时变量、数组中间值或短路径赋值造成的重复内存读。

实现思路：

1. 新增 `LocalStoreForwardPass`，按基本块顺序维护 `pointer -> stored value`。
2. 遇到 `store v, p` 时清空已有表，再记录 exact pointer 的最新值；这样不依赖 alias analysis。
3. 遇到 `load p` 且表中存在同一个 pointer identity，就用记录值替换该 load 的所有 uses。
4. 遇到 `call` 或其他 `store` 时清空表，避免跨副作用复用。
5. 后续 `DCEPass` 删除被替换后无用的 load。

安全边界：

- 只在同一基本块内做，不跨 CFG 边。
- 只接受 exact pointer identity，不猜测 GEP 等价、不做别名分析。
- 任意 store/call 都作为内存屏障；因此会漏掉不少可优化场景，但不会把不同地址的可能别名误前递。

### 阶段 13：小常数循环展开和归纳变量优化

目标：

- 对迭代次数小、循环体小的常数循环做展开，减少分支开销并暴露常量折叠机会。
- 识别最简单的归纳变量形式，减少循环内重复地址或步进计算。

实现思路：

1. 基于 LoopInfo 识别单 induction variable 的简单循环。
2. 要求上下界和步长是常量，循环体规模小。
3. 只做完全展开或小倍数展开。
4. 优先处理无 call、无复杂 CFG、单 latch、单 exit 的循环。
5. 展开后运行 `ConstantFoldPass`、`SimplifyCFGPass`、`DCEPass`。

安全边界：

- 不展开含 call、break/continue 复杂边、多个 latch 或多个 exit 的循环。
- 限制展开后指令数，避免代码膨胀导致性能下降。
- 先不做多面体优化，也不做后端 peephole。

### 性能优化2 当前补充：no-op COPY 汇编清理

背景：

- 继续对照 Hycompiler 后发现，分数差距不只在 IR Pass；后端缺少 strength reduction、后端 DCE、寄存器分配后冗余 COPY 清理等降本能力。
- 已验证的 SCEV、unroll、GCM 候选功能正确但性能明显回退，原因集中在 live range 变长、spill/stack 流量增加。

本次提交内容：

- 在最终 asm lowering 阶段跳过 `COPY` 源和目标为同一物理寄存器的情况，避免输出 `mv t0, t0` 或 `fmv.s ft0, ft0`。
- 不改变 IR、机器 CFG、寄存器分配和栈布局，只减少最终冗余汇编。
