## 记录规则

- 每个优化 commit 都新增一行性能记录。
- 每次记录必须写清楚测试命令、测试集、正确性结果和性能指标。
- 性能数字优先记录运行时表现；必要时补充生成汇编大小、编译耗时和超时数量。
- 不自动运行会改文件的格式化工具，例如 `rustfmt`。

建议记录字段：

- `阶段`：优化阶段名。
- `commit`：对应提交哈希；提交前可写 `未提交`。
- `优化内容`：本阶段实际做了什么。
- `测试命令`：用于复现实测数据的命令。
- `正确性`：功能测试是否通过。
- `性能指标`：总耗时、几何平均加速比、通过数、超时数等。
- `相对变化`：相对上一阶段或基线的变化。
- `备注`：风险、未覆盖场景、需要复测的点。

计分标准：

- `timer_ms`：运行库在 `-DOPT_TEST` 下输出的 `TOTAL` 或 `Timer@` 累加时间，主要衡量程序核心计算区，越低越好。
- `wall_ms`：qemu 运行进程的墙钟时间，包含读入大文件等非计时区成本，作为辅助指标。
- 后续判断优化是否有效以 `timer_ms` 为主，以 `wall_ms` 防止误判。

## 已有优化状态

当前 `-O1` 管线已经接入：

1. `VerifyPass`
2. `SimplifyCFGPass`
3. `Mem2RegPass`
4. `ConstantFoldPass`
5. `TrivialPhiPass`
6. `DCEPass`

当前能力：

- 常量条件分支折叠。
- 不可达块删除。
- 保守空跳转块旁路。
- 标量局部变量 mem2reg。
- 简单整数/浮点常量折叠。
- trivial phi 删除。
- 无副作用死指令删除。

当前主要缺口：

- `SimplifyCFGPass` 还没有完整合并 `bb -> succ` 这种单前驱单后继链。
- `ConstantFoldPass` 只做纯常量表达式，缺少 `x + 0`、`x * 1` 这类代数化简。
- `DCEPass` 还没有专门处理互相引用但整体无用的 phi 环。
- 缺少 LoopInfo、循环不变量外提和小循环展开等循环优化。
- 后端 MachineOpcode 当前没有 shift 指令，IR 层强度削弱要么先不做，要么先补机器指令支持。

## 接下来优化计划

### 阶段 1：增强 ConstantFoldPass

目标：

- 在现有纯常量折叠基础上补充安全代数化简。
- 优先清理循环体里的恒等计算，减少后端指令数和寄存器压力。

实现思路：

1. 参考 Hycompiler `RegularFold.cpp`，只选不改变语义的规则。
2. 对整数：
   - `x + 0 -> x`
   - `0 + x -> x`
   - `x - 0 -> x`
   - `x - x -> 0`
   - `x * 1 -> x`
   - `1 * x -> x`
   - `x * 0 -> 0`
   - `0 * x -> 0`
   - `x / 1 -> x`
   - `x % 1 -> 0`
3. 对浮点先只做保守规则：
   - `x + 0.0 -> x`
   - `x - 0.0 -> x`
   - `x * 1.0 -> x`
   - `x / 1.0 -> x`
4. 每次替换后维护 use-def 链，再交给 DCE 清理旧指令。

安全边界：

- 不做可能影响除零、溢出、NaN 或有符号右移语义的规则。
- 暂不做重关联和分配律。
- 暂不跨基本块做 CSE/GVN。

预期收益：

- 常见循环和矩阵类用例减少无用二元运算。
- 对总分预期 3%-8% 改善；如果低于 1%，检查规则是否未命中或后端是否又生成了等价冗余。

### 阶段 2：完善 SimplifyCFGPass

目标：

- 合并 `bb -> succ` 且 `succ` 只有一个前驱的基本块。
- 删除中间无意义跳转。
- 减少后端标签和无条件跳转数量。

实现思路：

1. 构建当前函数 CFG。
2. 遍历基本块 `bb`。
3. 只处理 `bb` 以无条件跳转结尾且唯一后继为 `succ` 的情况。
4. 要求 `succ` 只有一个前驱，即 `bb`，避免处理 critical edge。
5. 如果 `succ` 开头有 phi，则这些 phi 理论上只有一个 incoming，可以用 incoming value 替换 phi。
6. 删除 `bb` 末尾跳转。
7. 将 `succ` 中非 phi 指令移动到 `bb`。
8. 删除 `succ`，并把 `succ` 后继中的 phi incoming block 从 `succ` 改为 `bb`。
9. 每次改动后重新构建 CFG，并跑 `VerifyPass` 验证。

安全边界：

- 不处理多前驱后继，避免错误改写 phi。
- 不处理条件分支合并。
- 不处理可能需要拆边的 critical edge。

预期收益：

- 减少 IR 基本块数量。
- 减少生成汇编中的标签和无条件跳转。
- 为后续 DCE 和循环分析暴露更规整的 CFG。

### 阶段 3：增强 DCE

目标：

- 清理互相引用但没有外部使用的 phi 环。
- 扩展纯指令识别范围。

实现思路：

1. 保留 `store`、`call`、`br`、`ret` 等副作用指令。
2. 对无副作用且无 use 的指令迭代删除。
3. 对 phi 互引用图做小范围可达性检查：如果一个 phi 集合的所有 use 都在集合内部，则整体删除。
4. 删除前先清 operands，避免 use-def 链悬挂。

### 阶段 4：循环不变量外提 LICM

目标：

- 对性能热点中的嵌套循环，外提与循环迭代无关的纯计算。
- 先做保守 LICM，不处理别名复杂的 load/store。

实现思路：

1. 增加最小 LoopInfo：识别回边、header、latch、loop body。
2. 尝试识别 preheader；没有 preheader 的循环先跳过。
3. 只外提纯指令：二元运算、比较、zext/cast、常量地址计算。
4. 如果指令所有操作数都定义在循环外或已经被标记为 invariant，则移动到 preheader terminator 前。
5. 不外提 load/store/call/terminator/phi。

安全边界：

- 不做 alias analysis，因此内存读写不动。
- 不处理多出口或异常 CFG。
- 每移动一批后跑 `VerifyPass`。

### 阶段 5：小常数循环展开

目标：

- 对迭代次数小、循环体小的常数循环做展开，减少分支开销并暴露常量折叠机会。

实现思路：

1. 基于 LoopInfo 识别单 induction variable 的简单循环。
2. 要求上下界和步长是常量，循环体规模小。
3. 只做完全展开或小倍数展开。
4. 展开后运行 `ConstantFoldPass`、`SimplifyCFGPass`、`DCEPass`。

安全边界：

- 不展开含 call、break/continue 复杂边、多个 latch 或多个 exit 的循环。
- 限制展开后指令数，避免代码膨胀导致性能下降。
