## 2. hy 已实现的关键优化

参考项目：`Testing/Hycompiler`。

hy 的关键链路：

```text
structured pre-opt
  -> FlattenCFG
  -> GVN/DCE/Inline
  -> Mem2Reg
  -> Alias/DSE/DLE/GVN
  -> CanonicalizeLoop/LoopRotate/LICM/ConstLoopUnroll/SCEV/ADCE/GVN
  -> RegularFold/DCE/GVN/SimplifyCFG/Alias/DSE/DLE/Select/GCM/ADCE
  -> LateInline
  -> InlineStore/SynthConstArray/GCM/GVN
  -> repeated CanonicalizeLoop/LICM/SCEV/RemoveEmptyLoop/GVN/Fold
  -> Final ADCE/SimplifyCFG/InstSchedule
  -> RISC-V Lower/StrengthReduct/InstCombine/RvDCE/GVN/RegAlloc
```

对照后的关键差距：

| 大类 | hy 做法 | 当前差距 | 本轮判断 |
| --- | --- | --- | --- |
| helper / inline | `EarlyInline`、`Inline`、`LateInline` 后多轮 cleanup | 当前小 inline 不允许 load，因此 `hash(k){return k%hashmod;}` 这种热点 helper 仍保留 call | 本轮做只读全局标量 load helper inline，边界比 late inline 窄 |
| RISC-V StrengthReduction | 后端有独立 `StrengthReduct`/`InstCombine` | 当前 selector 只有零散规则；`many_mat_cal` 热循环仍有 `divw / 3` | 本轮只做 `/3` 常量除法降强，不重复 perf8 回退的完整 pow2 div/rem |
| Loop/SCEV | `LoopRotate`、`SCEV`、`ConstLoopUnroll` 和多轮 cleanup | 当前缺通用 SCEV；历史裸 SCEV/LCSSA/LoopRotate 容易回退或 timeout | 暂缓，等本轮低风险项后再复查 |
| 内存标量替换 | `InlineStore`、`SynthConstArray`、循环内存优化 | 当前 DLE/DSE 保守，矩阵/stencil 仍重访存 | 暂缓，风险在 alias 和 exit 写回 |
| GCM/调度 | 基于 loop depth 的 GCM | 当前历史回退，容易拉长 live range | 暂缓 |

## 4. 本轮执行清单

| 阶段 | 优化项 | 优先级 | 实现思路 | 预计收益 | 风险与取舍 |
| --- | --- | --- | --- | --- | --- |
| F1 | 只读全局标量 load 小 helper inline | P0 | 扩展 early inline：允许单块、小体量、无 store/call 的函数内联，load 仅限全局标量；目标命中 `hash(k){return k%hashmod;}`，避免保留热 call | 1%-4%，重点 `shuffle1`，也可能减少 call-live spill | 若扩大到内存 load 导致矩阵/crypto 回退，立即收窄或撤回 |
| E1 | RISC-V `/3` signed division strength reduction | P0 | 在 selector 中只把 `sdiv x, 3` 和 `sdiv x, -3` 降为 `mul + srai + subw` 的向零取整序列，新增 `srai` 机器指令；不做通用 magic division | 2%-8%，重点 `many_mat_cal-*` 的大循环 `/3` | 语义必须覆盖负数；若多指令序列放大寄存器压力且总分不升则撤回 |
| E2 | 机器级本块纯表达式 CSE | P1 | 在寄存器分配前，对同一 MachineBasicBlock 内的 `li/slli/add/addi/mul` 等无副作用纯表达式做 value numbering，删除重复地址计算；只处理虚拟寄存器和 `zero`，不跨块、不碰 load/store/call/branch | 1%-5%，重点 `sl2`、`many_mat_cal-*`、`transpose2` 的重复 GEP 片段 | 可能延长 live range、增加 spill；若矩阵/stencil 总分不升则撤回 |
| E3 | copy-aware 机器级本块 CSE | P1 | 在 E2 的 expression table 中记录同块 `COPY v <- u` 的别名，但不删除 copy 本身；让经 copy 传递的同一值参与纯表达式匹配 | 0.5%-3%，目标补上 E2 未合并的重复 GEP 乘法/加法 | 可能增加 source live range；若收益不稳定或局部回退扩大则撤回 |
| 复查 | 根据最新 CSV 追加必要项 | P1 | 每完成一项后复查热点；只有能影响多个热点组且不重复历史回退的方案才追加 | 不预设 | SCEV/内存标量替换若仍是唯一大缺口，放入后续文档或追加小范围实验 |

## 5. 暂缓项

| 优化 | 暂缓原因 |
| --- | --- |
| 完整 SCEV 地址递推 | 历史候选容易增加临时值和寄存器压力；当前先做 `/3` 与 helper inline 两个低风险高命中项 |
| 全函数 LCSSA / LoopRotate | 历史 LCSSA 导致 timeout；只能为具体 SCEV/A1 候选按需构造 |
| 循环内存标量替换 | alias、exit 写回和寄存器压力风险高，当前没有足够成本模型 |
| GCM | 历史上拉长 live range 后回退 |
| 完整 pow2 div/rem 降强 | perf8 三轮不达预期，源码已撤回 |
| Late pure inline | perf8 明显回退，本轮只做更窄的全局标量 load helper inline |
| 常量乘法 shift-add 降强 | perf8 明显回退，不重复 |

### E2 机器级本块纯表达式 CSE

状态：已完成，采用。

追加原因：E1/F1 都说明扩大 IR 或多指令降强会被寄存器压力吃掉；但最新稳定汇编中，`sl2` 和矩阵热点仍在同一基本块内重复生成相同的 `li + mul/slli + add` 地址片段。该优化放在寄存器分配前，只删除同块、无副作用、操作数完全相同的机器表达式，目标是减少最终汇编指令数，而不是构造新的循环递推。

实现摘要：

- 新增 `MachineLocalCSE`，在 `InstructionSelector` 后、图着色寄存器分配前运行。
- 每个 `MachineBasicBlock` 独立维护 expression table 和 vreg alias，只替换后续 use，不跨块。
- 只处理 `li/la/add/addi/addw/addiw/subw/mul/mulw/slli/and/or/xor/andi/xori/slt/seqz/snez` 等纯表达式。
- 跳过 load/store/call/branch；遇到 `call` 清空 expression table；跳过物理寄存器定义、非 `zero` 物理寄存器操作数和 def/use 同 vreg 的 in-place 指令。

构建与正确性：


| `matmul2` | 147 | 155.5 | 小幅回退 |

结论：E2 没有完全合并 `sl2` 的乘法地址片段，但能稳定减少同块常量和部分纯表达式重复；两轮总分均好于 baseline，收益覆盖局部回退，保留。

### E3 copy-aware 机器级本块 CSE

状态：已验证，未采用。

追加原因：E2 后 `sl2` 汇编仍有相同寄存器/常量形态的 `mul s2, 1000`、`slli s1, 2` 等重复片段，说明部分 IR 值经过 copy 后没有被 expression table 识别为同一值。E3 只在同一块内让 `COPY v <- u` 参与别名解析，不删除 copy，不跨块传播，期望提高 E2 命中率。

实现摘要：

- 尝试在 `MachineLocalCSE` 中记录 `COPY v <- u` 的同块别名。
- 不删除 copy，只让后续纯表达式 key 使用 copy source，避免破坏 phi edge copy 和跨块语义。
- vreg 重定义时清理指向该 vreg 的别名。

构建与正确性：

```bash
docker exec -w /workspace compiler-comp bash -lc 'cmake --build build-docker -j'
docker exec -w /workspace compiler-comp bash -lc 'TEST_ROOT=/workspace/Testing/contesttestcases bash scripts/run_ci_tests.sh -asm Testing/compiler2026-riscv-function --compiler ./build-docker/compiler --show-failures && TEST_ROOT=/workspace/Testing/contesttestcases bash scripts/run_ci_tests.sh -ir 2023_function 2025_function --compiler ./build-docker/compiler --show-failures && PERF_REPORT_FILE=/workspace/Testing/perf9-e3-copy-aware-machine-cse.csv TEST_ROOT=/workspace/Testing/contesttestcases CASE_RUN_TIMEOUT=180s CASE_COMPILE_TIMEOUT=180s CASE_LINK_TIMEOUT=180s MINIC_EXTRA_ARGS="-O1" bash scripts/run_ci_tests.sh -perf 2026_performance --compiler ./build-docker/compiler --show-failures'
```

结果：构建通过；ASM `140/140`；IR `239/239`；perf `60/60`。

性能：`Testing/perf9-e3-copy-aware-machine-cse.csv` timer 总和 `3510 ms`，wall 总和 `7985 ms`。相对 E2 两轮平均 `2838/6461.5` 明显回退。

现象：

- 汇编层 `sl2` 的 `mul` 从 17 降到 13、`slli` 从 10 降到 4，但 `mv` 上升，多个热点 live range 明显变长。
- 主要回退包括 `shuffle1 134.5 -> 260`、`many_mat_cal-3 254.5 -> 316`、`transpose2 174.5 -> 224`、`matmul2 155.5 -> 185`。

结论：copy-aware CSE 静态指令数更少，但寄存器压力和 copy 残留导致总分大幅回退。源码已撤回，不采用。

| ---: | --- | ---: | --- |

| 10 | `sl1` | 114.5 | E2 明显改善，剩余 stencil 地址/访存 |

后续仍可能带来大收益的方向：

| 方向 | 为什么不在本轮继续做 |
| --- | --- |
| SCEV / 循环地址递推 | 能覆盖矩阵、stencil、transpose 的最大热点，但历史实现多次因临时值和 live range 增加导致 spill 回退；E3 也再次证明“静态指令少”不等于 qemu 分数更好 |
| 循环内存标量替换 | 需要更强 alias 和 exit 写回模型；当前 DLE/DSE 边界不足，贸然做容易错编 |
| LoopRotate / 完整 LCSSA | 历史 LCSSA/rotate 组合有 timeout 和回退记录；若要重启，应先按单个热点构造按需 loop form |
| 更激进机器 copy propagation | E3 已验证会大幅回退，当前只保留 E2 的非 copy-aware 子集 |
| 通用常量除法/乘法降强 | E1、perf8 E1/C1 已验证多指令替换在当前后端下容易扩大压力，不再重复 |

最终结论：本轮保留 E2；F1、E1、E3 均撤回源码并记录。剩余大收益方向需要配套成本模型和寄存器压力评估，建议放到下一轮作为独立 SCEV/loop-address 课题，而不是在 perf9 中继续叠加风险。
