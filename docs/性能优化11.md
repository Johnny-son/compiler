# 性能优化11：面向剩余热点的内存优化闭环

本文档接替 `性能优化10.md`，用于记录 perf11 阶段的体系分析、baseline、优化候选、执行数据和取舍结论。perf10 已经补上 `MachineDCE` 与 `MachineInstCombine`，后端对冗余机器指令和地址偏移的承接能力明显增强；perf11 不继续堆零散 peephole，而是回到 IR 内存体系，优先处理当前热点中仍然可见的“无用全局写”和“同一符号地址重复 load”。

执行原则保持前几轮一致：每个优化点先写进本文档，再单独实现、单独测试、单独记录。功能错或性能明显回退则撤回源码，只保留记录；性能收益明确则保留源码并独立 commit。禁止自动运行会修改文件的 `rustfmt`。

## 1. 当前优化体系

| 层级 | 当前已有能力 | perf11 判断 |
| --- | --- | --- |
| CFG/SSA | `SimplifyCFG`、`Mem2Reg`、`TrivialPhi`、`LoopCanonicalize` 的 preheader/dedicated-exit 子集 | 能支撑基础 cleanup；完整 LoopRotate/LCSSA/SCEV 仍缺 |
| 标量优化 | `ConstantFold`、`LocalCSE`、`ADCE`、`DCE`、窄 `LoopClosedForm` | 基础表达式和死代码处理可用；缺 SCCP、完整 GVN、range-aware fold |
| 内存优化 | `SingleStoreAlloca`、`LocalStoreForward`、`DLE`、`DSE`、`MemoryAlias` | 有保守 DLE/DSE，但对未知 offset 的同一指针 load、模块级 write-only global 缺处理 |
| 循环优化 | `LoopCanonicalize`、`LoopClosedForm`、`LICM` | 剩余热点需要 SCEV/地址递推，但历史裸 SCEV/GCM/unroll 多次被寄存器压力反噬 |
| 函数级优化 | 小纯函数 inline、RuntimeMemoize、TailCallOpt、后端 helper 识别 | 递归和简单 helper 已吃到大收益；扩大 inline 需要成本模型 |
| 后端优化 | GEP prefix cache、compare-branch fusion、copy coalescing、MachineLocalCSE、MachineDCE、MachineInstCombine | perf10 后后端承接能力明显增强；下一步更应减少进入后端的无用内存操作 |

## 2. Hy / 现代编译器参考

| 方向 | Hy / 现代编译器做法 | 当前项目差距 | perf11 取舍 |
| --- | --- | --- | --- |
| Dead Store Elimination | 现代 DSE/GlobalOpt 会删除不可观察写；Hy 也通过多轮 DCE/GVN/存储清理让无用内存操作尽早消失 | 当前 DSE 更偏 block/data-flow 局部，未做模块级 global 是否被读取/逃逸分析 | 本轮做 A1：write-only global store elimination |
| Redundant Load Elimination | GVN/DSE/DLE 通常会把同一内存 SSA 地址的重复 load 合并，即使无法算出常量 offset | 当前 `MemoryAlias` 对变量 GEP 只有 unknown offset，导致同一个 GEP 指针连续 load 也无法复用 | 本轮做 A2：符号化 DLE，先只处理同一指针 Value |
| SCEV / 地址递推 | Hy/Sisyphus 等高分实现会用 SCEV 理解线性 GEP、trip count、递推地址 | 当前缺成本模型，历史裸实现回退；perf10 刚补了后端 cleanup，但仍需候选报告 | perf11 先不直接写 SCEV，等 A1/A2 后复查 |
| 常数除法降强 | 现代后端会用 magic multiply/shift 替换常数除法 | `/3` magic 历史曾回退，原因是指令数与寄存器压力抵消收益 | 本轮只作为复查项，不在没有新证据时强行重做 |

## 3. perf11 baseline 热点

| 排名 | 用例 | timer_ms | wall_ms | 热点归类 |
| ---: | --- | ---: | ---: | --- |
| 1 | `many_mat_cal-3` | 253 | 263 | 矩阵地址/访存、`/3`、重复 load |
| 2 | `many_mat_cal-2` | 251 | 261 | 同上 |
| 3 | `many_mat_cal-1` | 239 | 249 | 同上 |
| 4 | `sl2` | 211 | 219 | 三维 stencil，初始化写和多 GEP/load |
| 5 | `transpose2` | 173 | 181 | stride 地址、同一元素重复 load |
| 6 | `matmul2` | 148 | 174 | 矩阵访存和 `%2` 分支 |
| 7 | `01_mm2` | 134 | 152 | 矩阵访存 |
| 8 | `h-4-03` | 134 | 141 | helper/常数除模/循环标量 |
| 9 | `shuffle1` | 110 | 603 | 链式访存和 hash/rem |
| 10 | `sl1` | 109 | 118 | stencil |

从 IR 复查看到的具体缺口：

- `sl2` 中全局数组 `y` 只被初始化写入，后续没有 load，也没有把 `y` 或其 GEP 地址传给外部调用；这些 store 是模块级不可观察写。
- `many_mat_cal` 的最终求和循环有同一个 GEP 指针连续 load 两次；`transpose2` 中 `matrix[i * rowsize + j]` 也出现先 load 到 `curr` 后再次从同一指针 load 的形态。
- 这些问题位于当前前十热点，不依赖大范围 CFG 改写，风险比直接上 SCEV/LoopRotate 更可控。

### A1 Write-only Global Store Elimination

状态：已完成，保留。

实现内容：

- 新增 `WriteOnlyGlobalStoreElimPass`，放在第二轮 `DSE` 后、`ADCE/DCE` 前。
- 模块级统计每个全局对象的读和逃逸情况。
- 如果某个全局对象没有任何 load，且其地址或基于它的 GEP 没有作为 call/return/未知指针用途逃逸，则删除写入该全局对象的 store。
- 对 `GetElementPtrInst` 只视为地址计算，不视为逃逸；对 call/return/未知非 GEP 指针用途一律保守视为逃逸。
- 删除 store 后依赖后续 `ADCE/DCE` 清理只剩地址计算的 GEP。

局部 IR 检查：

```bash
docker exec -w /workspace compiler-comp bash -lc './build-docker/compiler -S -I -O1 Testing/contesttestcases/2026_performance/sl2.sy -o /tmp/sl2.a1.ll && grep -E "@y|y\\.idx|store i32 0" /tmp/sl2.a1.ll || true'
```

结果：优化后 IR 仍保守保留 `@y` 全局声明，但 `y.idx` 和 `store i32 0` 消失。`MINIC_IR_PASS_STATS=1` 显示 `WriteOnlyGlobalStoreElim` 在 `sl2` 上删除 1 条 store，后续 `ADCE` 再清理 12 条配套地址计算/死值。
