# 性能优化5：大优化候选与 O2 管线规划

本文档接替 `性能优化4.md`，只负责调研和规划下一轮值得实现的重大优化，不实现任何优化代码。调研范围包括当前项目源码、现有 pass pipeline、后端 lowering/寄存器分配、测试脚本、已有性能记录，以及 `Testing/Hycompiler` 这个既有文档中称为 Hycompiler / hw 的参考项目。

本轮结论：当前项目已经完成了不少高收益特判和后端承载优化，继续堆局部 peephole 的收益会很不稳定。`性能优化5` 应优先把剩余热点导向几类“大优化”：循环结构补全、SCEV 地址递推、机器级 cleanup/降强、ADCE + 多轮 cleanup 收敛；其次再推进完整 GVN、循环内存标量替换、TCO、SCCP 和小常数循环展开。

## 3. 当前已有优化总结

当前 `-O1` 管线在 `src/main.cpp` 中实际注册顺序如下：

```text
Verify
  -> SimplifyCFG
  -> Mem2Reg
  -> SingleStoreAlloca
  -> InlineSimpleFunction
  -> RuntimeMemoize
  -> ConstantFold
  -> LocalCSE
  -> LocalStoreForward
  -> DLE
  -> DSE
  -> SimplifyCFG
  -> TrivialPhi
  -> SimplifyCFG
  -> LoopCanonicalize
  -> LoopClosedForm
  -> SimplifyCFG
  -> LICM
  -> LocalCSE
  -> LocalStoreForward
  -> DLE
  -> DSE
  -> DCE
```

每个关键 transform 后都插入了 `VerifyPass`，这是当前项目稳定性的一个优势。

| 层级 | 已有优化 | 当前状态判断 |
| --- | --- | --- |
| CFG | `SimplifyCFGPass` 折叠常量分支、phi/icmp 分支中转块、删除不可达块、bypass 空跳转块 | 可用，但不是完整 CFG simplify；缺 general jump threading、critical edge split、block merge、dedicated exits |
| SSA / mem2reg | `Mem2RegPass` 基于支配边界插 phi，沿 dominator tree rename；只提升 int/float 标量 alloca | 标量 SSA 比较完整；数组、指针、地址逃逸不提升是正确边界；缺 LCSSA |
| Phi 清理 | `TrivialPhiPass` 删除所有 incoming 相同的 phi；后端 `Phi register lowering` 用稳定机器 vreg + 边拷贝 | 基础清理和后端承接较好；缺 LCSSA exit phi、parallel copy 环处理的更强模型 |
| 常量折叠 | `ConstantFoldPass` 支持 int/float 常量二元、整数恒等式、同值比较、`zext`、只读全局标量 load、布尔分支规约 | 简单折叠完整；缺 SCCP、range-aware fold、跨 CFG 常量边删除 |
| CSE/GVN | `LocalCSEPass` 沿支配树复用纯表达式，覆盖 binary/icmp/fcmp/zext/cast/gep | 已超过单块 CSE，但仍不是完整 GVN；不做 value numbering、commutative canonicalization、纯 call、phi value numbering |
| DCE | `DCEPass` 删除无 use 且无副作用的纯指令 | 只是普通 DCE；缺 ADCE，删不掉互相引用的死 phi/死环和不可达控制依赖产物 |
| 内存优化 | `MemoryAlias` base+offset；`DLE` 可用 load dataflow；`DSE` 同块覆盖 store、同值 store、未逃逸局部数组 backward DSE；`LocalStoreForward` 同块 exact pointer store-to-load | 保守可用；unknown offset/call/形参别名边界严格；缺 InlineStore、循环内存标量替换、dead global store、只读数组合成 |
| 循环基础 | `LoopAnalysis` 自然循环；`LoopCanonicalizePass` 补 dedicated preheader 并重写 header phi | 只有 preheader；缺 LCSSA、dedicated exits、single latch 规范、LoopRotate、RemoveEmptyLoop |
| LICM | `LICMPass` 外提安全纯计算、GEP、比较、cast、zext；可外提无 call 且函数无 store 的全局标量 load | 保守可用；不会外提普通 load，不用 alias，不做成本/寄存器压力模型；A4 alias-LICM 曾回退 |
| 循环特化 | `LoopClosedFormPass` 闭式替换窄模式全局标量递推 | 对 `conv2d` 很有效，但模式非常窄；不是通用 SCEV |
| 函数优化 | `InlineSimpleFunctionPass` 内联单块、非 void、最多 8 条纯计算小函数；`RuntimeMemoizePass` 有界二参重叠自递归 memo；后端 helper equivalence 识别 bitwise/add/sub/modmul/minmax 等 | 特判收益很大；缺调用图驱动 inline、late inline、TCO、参数常量特化 |
| 后端指令选择 | `InstructionSelector` 做小立即数 `add/sub`、乘 0/1/-1/2^k、除 1、模 1/-1、GEP scale `slli`、compare-branch fusion、GEP prefix cache、local value cache | 已经有多项高收益 lowering 优化；缺统一机器级 InstCombine/StrengthReduction/RvDCE |
| 寄存器分配 | 图着色 RA；GPR 使用 `t0-t6 + s1-s11`；call-live GPR 限制到 callee-saved；COPY coalescing 和 affinity coloring；按实际使用保存恢复 `s*` | 比早期完整很多；spill 仍是直接 reload/store，FPR callee-saved 和 rematerialization 较弱 |
| 栈帧/汇编 | 紧凑 SP-relative epilogue，小/中栈帧直接从 `sp` 恢复 `ra/fp`；`MachineAsmLowering` 删除同寄存器 COPY | 返回路径已优化；缺基本块布局、post-RA cleanup、机器级死定义删除 |
| Pipeline | 已有固定两轮 memory cleanup 和 loop 后 cleanup | 有顺序但不是 O2 fixpoint；大优化后缺统一 `Fold/GVN/ADCE/SimplifyCFG/MachineCleanup` 闭环 |

差距总览：

| 大类 | hw 做法 | 当前项目差距 | 是否建议借鉴 |
| --- | --- | --- | --- |
| Pipeline 分层 | structured pre-opt、flatten 后 GVN/DCE/Inline/Mem2Reg/Loop/LateInline/FinalCleanup，多处重复 cleanup | 当前是单条固定 O1 管线，cleanup 轮次少，没有 O2 fixpoint | 建议借鉴“分阶段 + 小轮次收敛”，不要照搬全部结构化 IR |
| CFG/Loop 形态 | `CanonicalizeLoop(lcssa)`、`LoopRotate`、`RemoveEmptyLoop` | 当前只补 preheader；没有 LCSSA/dedicated exits/rotate | 强烈建议实现，是 SCEV/unroll/scalar replace 前置 |
| 标量全局优化 | `GVN` 基于支配树值编号，`GCM` 基于 loop depth schedule early/late，`AggressiveDCE` 反向标记 live | 当前 LocalCSE 不是完整 GVN，DCE 不是 ADCE，GCM 候选曾回退 | 建议先做 ADCE + GVN，再谨慎重试 GCM |
| 循环强优化 | `SCEV` 标记递增属性，重写地址递推；`ConstLoopUnroll`、多轮 loop cleanup | 当前只有 `LoopClosedFormPass` 窄特判，没有通用 SCEV/unroll | 建议作为 P0/P1，但必须先补 loop shape 和机器 cleanup |
| 内存优化 | `Alias -> DSE -> DLE` 多轮；`DAE`、`InlineStore`、`SynthConstArray` | 当前 DLE/DSE 保守可用，但没有参数/全局/常量数组和 late memory cleanup | 建议做循环内存标量替换和 InlineStore 子集，常量数组放 P2 |
| 函数优化 | `EarlyInline`、`Inline`、`LateInline`、`TCO` | 当前只有小纯函数 inline、runtime memo、后端 helper 等价 | 建议优先做 TCO；通用 late inline 放 P1/P2 |
| RISC-V 后端 | `StrengthReduct -> InstCombine -> RvDCE -> GVN -> RegAlloc`；RegAlloc 内有 latePeephole/tidyup | 当前很多规则写在 selector 中，缺独立机器级 cleanup；spill/remat 较弱 | 强烈建议实现 liveness-aware 子集 |
| 结构化 pre-opt | `RaiseToFor`、`ColumnMajor`、`Fusion`、`Parallelizable`、`TidyMemory` | 当前 AST/IR 已 flatten，缺结构化 for 层 | 不建议短期照搬，成本高且会重写前端/IR 形态 |

可借鉴但不能照搬的点：

- hw 的 IR 是 MLIR 风格 Op/Region，当前项目是 LLVM 风格 BasicBlock/Instruction；算法思想可借鉴，代码结构不能直接搬。
- hw 的结构化 pre-opt 依赖尚未 flatten 的 while/for Region，当前项目不具备这个中间层。
- hw 的 `GCM` 需要 loop depth 和更强 GVN/ADCE 承接；当前项目 perf2 已验证 GCM 子集会拉长 live range 并回退，所以不能裸上。
- hw 的 signed division magic number 降强很强，但语义边界复杂；当前只能在 RISC-V 功能和性能全验证后分阶段做。

| --- | --- | --- | --- | --- | --- | --- | --- |

| E1 | MachineDCE + MachineInstCombine + RISC-V StrengthReduction | P0 | 缺失；selector 内有零散规则 | 3%-8%，并承接循环优化产物 | 中高 | MachineLiveness、RA | 建议优先 |
| B1 | ADCE + O2 cleanup fixpoint | P0 | DCE 仅删无 use 纯指令；pipeline 非 fixpoint | 2%-8%，降低大优化副作用 | 中 | SimplifyCFG、TrivialPhi、LocalCSE/GVN | 建议优先 |
| B2 | 完整 GVN / value numbering | P1 | LocalCSE 支配树表达式复用，但非完整 GVN | 3%-10%，吸收循环和 inline 产物 | 中高 | ADCE、支配树 | 建议 |
| A1 | 循环内存标量替换 / invariant address scalar replacement | P1 | 缺失；DLE/DSE 保守 | 3%-10%，矩阵/stencil/reduce 热点 | 高 | C1、MemoryAlias、D1、ADCE | 建议 |

| B3 | SCCP 稀疏条件常量传播 | P1 | 第一版候选功能过但性能不升，未提交 | 1%-6%，更依赖 ADCE/CFG cleanup | 中高 | B1、SimplifyCFG | 建议重做但不先做 |
| F1 | Late inline + inline 后二次优化管线 | P1 | 只有小单块 inline 和 helper 特判 | 2%-8%，call-heavy/helper 热点 | 中 | B1/B2/E1 | 建议 |
| A2 | InlineStore / 跨块 store-to-load forwarding | P1 | 有 DLE/LocalStoreForward 子集 | 1%-5%，内存热点 | 中高 | MemoryAlias、B1 | 谨慎建议 |
| R3 | Spill 优化 / rematerialization / FPR callee-saved | P1 | 图着色可用，spill 直接 reload/store | 1%-5%，承接高寄存器压力 | 高 | E1、RA | 建议在 D1 后看压力 |
| A3 | 只读全局/常量数组合成、DeadGlobalStore | P2 | 只折叠 const 标量 load | 0%-5%，依赖用例 | 中 | MemoryAlias、初始化解析 | 可选 |
| G1 | GCM 全局代码移动 | P2 | 候选曾明显回退 | 理论 1%-5%，但风险高 | 高 | C1、B2、E1、压力模型 | 暂缓 |
| C2 | 通用 jump threading / block layout | P2 | CFG 有少量中转块折叠 | 0%-3%，偏锦上添花 | 中 | SimplifyCFG | 暂缓 |
| P2-X | 结构化 loop fusion / column-major / parallelize / vectorize | P2 | 缺结构化 IR；RV 无 SIMD | 不稳定 | 很高 | IR 重构 | 暂不建议 |

## 6. 详细优化方案

### C1 LoopSimplify：LCSSA + dedicated exits + LoopRotate

- 优先级：P0。
- 当前项目状态：`LoopCanonicalizePass` 只为单入口循环补 dedicated preheader，并重写 header phi；`LoopAnalysis` 能识别 header/latch/body/exit/preheader，但没有 LCSSA、dedicated exits、LoopRotate、RemoveEmptyLoop。
- hw 参考：`Testing/Hycompiler/src/opt/CanonicalizeLoop.cpp`、`Testing/Hycompiler/src/opt/LoopRotate.cpp`、`Testing/Hycompiler/src/opt/RemoveEmptyLoop.cpp`、`Testing/Hycompiler/src/opt/LoopPasses.h`。
- 当前问题：后续 SCEV/unroll/scalar replacement/GCM 无法依赖稳定 loop shape；复杂 exit 上的值使用也没有 LCSSA 保护。
- 优化目标：形成“preheader + header + latch + dedicated exit + LCSSA exit phi”的稳定循环形态；必要时旋转 while/do-while 形态，让归纳变量和退出条件更容易识别。
- 实现思路：先在现有 `LoopCanonicalizePass` 上增量实现 dedicated exit splitting；再对 loop-defined value 在 exit 外使用插入 LCSSA phi；最后只对低风险单 latch 循环做 LoopRotate。
- 涉及模块：`src/ir/passes/LoopAnalysis.*`、`LoopCanonicalizePass.*`、`IRCFG.*`、`PhiInst.*`、`VerifyPass.*`。
- 前置依赖：现有 CFG、支配树、phi incoming 更新能力。
- 预期收益：直接 timer 可能只有 0%-2%，但能解锁 D1/D2/A1/GCM，是后续大优化共同前置。
- 风险点：phi incoming 修补、critical edge、exit value rewrite 容易引入 verify 错或错编。
- 功能测试：`compiler2026-riscv-function` 必须 `140/140`；额外挑 `while/for/break/continue`、多 exit、嵌套循环、小 phi 用例输出 IR 核对。
- 性能测试：先要求不明显退化；后续 D1/D2 命中率提高才是主要收益。
- 建议执行顺序：先 dedicated exits，再 LCSSA，最后 LoopRotate；每个子点单独提交和记录。
- 是否建议实现：建议优先实现。

### D1 通用 SCEV 地址递推 / loop strength reduction

- 优先级：P0。
- 当前项目状态：`LoopClosedFormPass` 只处理 `conv2d/get_random` 类单全局递推闭式化；没有通用归纳变量、trip count、线性 GEP 递推。
- hw 参考：`Testing/Hycompiler/src/opt/SCEV.cpp`、`Testing/Hycompiler/src/opt/LoopUnroll.cpp`、`Testing/Hycompiler/src/rv/StrengthReduct.cpp`。
- 当前问题：`many_mat_cal/sl/matmul/transpose/01_mm` 中大量 `base + i * stride + j` 每轮重复计算；当前 GEP prefix cache 只在同一基本块内复用前缀，跨迭代无能为力。
- 优化目标：识别 `i = phi(start, i + step)`、退出比较、常量 stride GEP，把循环内重复乘加地址计算改为 loop-carried 递推值，或将不变 scale/row base 外提。
- 实现思路：只先支持 int32 常量 step、单 latch、单 exiting、无复杂 side effect 的循环；优先处理地址计算，不急于替换普通算术；新增递推 phi 后立刻跑 B1 cleanup。
- 涉及模块：`LoopAnalysis`、`LoopCanonicalizePass`、新增 `SCEVPass` 或扩展 `LoopClosedFormPass`、`GetElementPtrInst`、`BinaryInst`、`PhiInst`。
- 前置依赖：C1、B1、E1；否则 perf2 的 SCEV/GEP split 回退可能重现。
- 预期收益：对矩阵和三维 stencil 类热点预期 5%-15%；重点观察 `many_mat_cal-*`、`sl*`、`matmul*`、`transpose*`、`01_mm*`。
- 风险点：新增 phi 会增加寄存器压力；地址递推错一个 offset 就会错编；变量 trip count 和有符号溢出边界要保守。
- 功能测试：新增小型二维/三维数组、不同 stride、零迭代、单次迭代、嵌套循环用例；官方 ASM `140/140`。
- 性能测试：`Testing/perf4-g1-riscv.csv` 为相邻历史基线，正式实现时重新补同环境基线后比较。
- 建议执行顺序：先 row-base 外提，再单层 GEP 递推，再嵌套循环地址递推；每步后跑 cleanup。
- 是否建议实现：建议优先实现。

### E1 MachineDCE + MachineInstCombine + RISC-V StrengthReduction

- 优先级：P0。
- 当前项目状态：selector 内已有 `addiw` 小立即数、乘 2^k、GEP `slli`、compare-branch fusion、GEP prefix cache 等规则；但没有独立的机器级 DCE/InstCombine/StrengthReduction pass。
- hw 参考：`Testing/Hycompiler/src/rv/StrengthReduct.cpp`、`Testing/Hycompiler/src/rv/InstCombine.cpp`、`Testing/Hycompiler/src/rv/RvDCE.cpp`、`Testing/Hycompiler/src/main/main.cpp` 中 RV pipeline。
- 当前问题：IR 大优化会产生更多 machine vreg、copy、li/add 地址链和 dead virtual defs；当前只能靠 RA/coalescing/asm lowering 局部消化，缺系统性 cleanup。
- 优化目标：在 RA 前增加 liveness-aware machine cleanup：删除无副作用 dead def；合并 `li + add/sub/and/shift`；合并 `addi + load/store offset`；保守做乘法/除法/取模常量降强。
- 实现思路：先做只删 dead COPY/LI/纯算术且 def 无 live/use 的 MachineDCE；再做 offset combine；最后才做 signed div/rem 常量降强，并逐条验证语义。
- 涉及模块：`MachineIR`、`MachineLiveness`、`MachineCFG`、`InstructionSelector` 后的后端 pipeline、`GraphColoringRegisterAllocator` 前置清理。
- 前置依赖：当前 MachineLiveness 已可用；需要避免破坏二地址式 vreg 更新和 call/memory/branch side effect。
- 预期收益：单独 3%-8%；更重要是承接 D1/D2/B2，避免新增 IR 被栈流量抵消。
- 风险点：perf3 的 E2 第一版曾因 copy 前递拉长 live range 而回退；本轮必须用 use-count/liveness 和成本模型做窄子集。
- 功能测试：官方 ASM `140/140`；重点测 call、float、large stack offset、spill、多返回块。
- 性能测试：完整 2026 perf，记录汇编指令数、`mv/li/add/div/rem` 统计作为辅助指标。
- 建议执行顺序：MachineDCE -> offset combine -> simple strength reduction -> signed div/rem magic。
- 是否建议实现：建议优先实现，但每个规则要小步提交。

### B1 ADCE + O2 cleanup fixpoint

- 优先级：P0。
- 当前项目状态：`DCEPass` 只删除无 use 纯指令；pipeline 是固定顺序，没有统一 O2 cleanup 小循环。
- hw 参考：`Testing/Hycompiler/src/opt/AggressiveDCE.cpp`、`Testing/Hycompiler/src/main/main.cpp` 的多轮 `GVN/RegularFold/DCE/SimplifyCFG/AggressiveDCE`。
- 当前问题：循环优化、inline、SCEV 产生的新 phi、死分支、死计算无法稳定收敛；普通 DCE 删不掉互相引用的死 phi 环。
- 优化目标：实现从 `ret/store/impure call/terminator` 反向标记 live 的 ADCE；并抽出 O2 cleanup round：`ConstantFold -> TrivialPhi -> LocalCSE/GVN -> ADCE -> SimplifyCFG`，大优化后重复 2-3 轮或直到无变化。
- 实现思路：ADCE 先只删纯指令，不删 terminator；第二阶段允许删不可达/无效控制依赖时交给 SimplifyCFG。
- 涉及模块：新增 `ADCEPass`、`IRPassManager`、`DCEPass`、`SimplifyCFGPass`、`VerifyPass`。
- 前置依赖：无强依赖，可先做；如果 pass 当前不返回 changed，需要增加内部统计或保持固定小轮数。
- 预期收益：2%-8%；更多体现为让 D1/D2/F1 的收益稳定。
- 风险点：如果把 branch 处理得太激进会破坏 CFG；call 纯度目前没有完整分析，未知 call 必须保守 live。
- 功能测试：官方 ASM `140/140`；构造死 phi 环、死循环计算、dead branch、纯计算链用例。
- 性能测试：2026 perf；同时记录 IR 指令数下降和编译时间变化。
- 建议执行顺序：先 ADCE transform，再封装 cleanup round，最后在 D1/D2/F1 后接入。
- 是否建议实现：建议优先实现。

### B2 完整 GVN / value numbering

- 优先级：P1。
- 当前项目状态：`LocalCSEPass` 实际沿 dominator tree 复用表达式，但 key 依赖 Value 指针，不做值编号、交换律规范、phi value numbering、纯 call 识别。
- hw 参考：`Testing/Hycompiler/src/opt/GVN.cpp`。
- 当前问题：SCEV/unroll/inline 之后，等价表达式不一定指针相同；当前 CSE 无法充分吸收。
- 优化目标：基于支配树建立 value number，覆盖常量、binary、icmp/fcmp、cast/zext、GEP、trivial phi；交换律 op 对 operand number 排序。
- 实现思路：先不碰 load/call；复用现有 DominanceInfo；把 LocalCSE 升级或新增 `GVNPass`，后接 ADCE。
- 涉及模块：`LocalCSEPass` 或新增 `GVNPass`、`IRCFG`、各 Instruction 类型。
- 前置依赖：B1 更好，但可并行推进。
- 预期收益：3%-10%，尤其吸收 loop/unroll 后重复地址和比较。
- 风险点：把非纯 op 纳入 GVN 会错；GEP type/indices 的 key 必须包含类型和顺序。
- 功能测试：表达式等价、交换律、phi 同值、GEP 等价、不等价 load/call 用例。
- 性能测试：2026 perf；重点观察 `many_mat_cal/sl/matmul/transpose`。
- 建议执行顺序：纯 scalar/GEP GVN -> trivial phi numbering -> cleanup round 接入。
- 是否建议实现：建议，但排在 C1/B1/E1 之后更稳。

### A1 循环内存标量替换 / invariant address scalar replacement

- 优先级：P1。
- 当前项目状态：DLE/DSE 已能处理 exact/base+offset 的冗余 load/store，但没有把循环内固定地址 load-compute-store 变成标量 phi。
- hw 参考：`Testing/ref-sisyphus/src/opt/ScalarReplace.cpp`（前文已参考）、hw 的 `LICM.cpp`、`InlineStore.cpp` 和多轮 `Alias/DSE/DLE`。
- 当前问题：矩阵、stencil、归约类循环中，固定地址或可证明不别名地址反复 load/store，当前优化只做局部前递，跨迭代不能消掉。
- 优化目标：对不逃逸 alloca/global 精确地址，在 loop preheader load 成 scalar，loop 内用 phi/update，exit 写回。
- 实现思路：先只处理单 exit、单 store、无 may-alias call 的 local alloca 精确 offset；全局和形参地址后置。
- 涉及模块：`MemoryAlias`、`LoopAnalysis`、`DLEPass`、`DSEPass`、`PhiInst`。
- 前置依赖：C1、B1、D1。
- 预期收益：3%-10%，重点 `sl*`、`many_mat_cal-*`、`matmul*`。
- 风险点：alias 证明不足会错编；exit 写回位置和零迭代语义复杂。
- 功能测试：reduce、stencil、小矩阵、early exit、break/continue、别名形参负例。
- 性能测试：2026 perf，重点矩阵/stencil 组。
- 建议执行顺序：未逃逸 local alloca -> 精确 GEP -> loop-carried scalar -> exit store。
- 是否建议实现：建议，但不要早于 C1/B1。

### D2 小常数循环展开 + 展开后 cleanup

- 优先级：P1。
- 当前项目状态：缺失；perf2 的 SCEV/unroll 候选功能通过但 timer 明显回退。
- hw 参考：`Testing/Hycompiler/src/opt/LoopUnroll.cpp`、`Testing/Hycompiler/src/opt/SCEV.cpp`。
- 当前问题：固定 kernel、小 trip count 循环仍有分支和归纳变量成本，但无成本模型展开会导致代码膨胀和寄存器压力。
- 优化目标：只展开固定小 trip count、低 body cost、低 phi 数、无复杂 call/store 的循环；展开后立刻 cleanup。
- 实现思路：先只支持 trip count <= 4/8 的单块循环；设置 IR 指令增长上限；对已有回退 case 做黑名单或成本规则。
- 涉及模块：`LoopAnalysis`、`LoopCanonicalizePass`、`PhiInst`、`BasicBlock` 克隆。
- 前置依赖：C1、D1、B1、E1。
- 预期收益：3%-10%，命中固定 kernel 时更高。
- 风险点：代码膨胀、live range 增长、I-cache 和 RA 回退。
- 功能测试：固定 0/1/2/4 次循环、嵌套小循环、phi 多 incoming。
- 性能测试：2026 perf；收益接近噪声时至少复跑一次。
- 建议执行顺序：只展开最窄模式，负优化立即撤回。
- 是否建议实现：建议但必须晚于 C1/E1。

### R2 Tail Call Optimization / 尾递归转循环

- 优先级：P1。
- 当前项目状态：缺失；`RuntimeMemoizePass` 只针对二参重叠自递归，不命中 `h-1-03` 的单路径/多分支尾递归。
- hw 参考：`Testing/Hycompiler/src/pre-opt/TCO.cpp`。
- 当前问题：`h-1-03` 当前 timer `543 ms`，函数 `fun(n, dep)` 的递归调用均处于 tail position，call/return 和栈帧成本明显。
- 优化目标：把同一函数的 tail recursive call 改写为参数更新 + 跳回入口循环。
- 实现思路：在 IR 层识别 `return call self(args)`；创建 loop header phi 承接形参；把 tail call block 改成跳转回 header。
- 涉及模块：`CallInst`、`ReturnInst`、`BranchInst`、`PhiInst`、`Function`。
- 前置依赖：Mem2Reg/CFG/Verify；若先有 C1 更稳。
- 预期收益：对 `h-1-03` 可能明显；总分预计 1%-5%，取决于输入。
- 风险点：多返回块、非 tail call、副作用参数求值顺序、递归深度边界。
- 功能测试：单尾递归、分支尾递归、非尾递归负例、带多个参数更新。
- 性能测试：重点看 `h-1-03`，同时确认 `knapsack_naive-*` 不被误改。
- 建议执行顺序：作为 C1/B1 后的独立 P1 阶段。
- 是否建议实现：建议。

### B3 SCCP 稀疏条件常量传播

- 优先级：P1。
- 当前项目状态：perf3 第一版 SCCP 功能正确但 timer 小幅回退，未提交。
- hw 参考：hw 没有直接 SCCP 主线；可参考 Iroha 方向，hw 的 `RegularFold/SimplifyCFG/AggressiveDCE` 提供 cleanup 思路。
- 当前问题：当前常量传播只在表达式局部折叠，不能通过 executable edge 删除不可达 incoming 和不可达边。
- 优化目标：实现 `undef/const/overdef` lattice，按 executable edge 传播 phi 和分支，替换常量后交给 SimplifyCFG/ADCE。
- 实现思路：不要单独追求 SCCP 首轮收益；必须和 B1 cleanup 组合，且只替换确定常量，不做 risky range。
- 涉及模块：新增 `SCCPPass`、`SimplifyCFGPass`、`TrivialPhiPass`。
- 前置依赖：B1。
- 预期收益：1%-6%，对常量开关、inline 后常量实参、递归边界判断有帮助。
- 风险点：phi incoming 只应看 executable predecessor；不可达边删除要和 CFG 同步。
- 功能测试：常量分支、循环 phi、不可达 incoming、overdefined 负例。
- 性能测试：2026 perf，收益小则复跑。
- 建议执行顺序：B1/B2 后重做。
- 是否建议实现：建议但不是第一批。

### F1 Late inline + inline 后二次优化管线

- 优先级：P1。
- 当前项目状态：`InlineSimpleFunctionPass` 只内联单基本块、最多 8 条纯计算指令；后端 helper equivalence 是 lowering 特判，不等于 IR inline。
- hw 参考：`Testing/Hycompiler/src/opt/Inline.cpp`、`LateInline.cpp`、`EarlyInline.cpp`。
- 当前问题：一些 helper 通过后端特判被优化，但 IR 层看不到 inline 后的常量传播、GVN、ADCE 机会。
- 优化目标：基于调用图和成本模型做 late inline；inline 后立即跑 B1/B2 cleanup。
- 实现思路：先扩展到小型多块、无 store/无 impure call、返回值单一的 helper；递归函数不 inline。
- 涉及模块：`InlineSimpleFunctionPass`、`CallInst`、CFG block clone。
- 前置依赖：B1/B2/E1。
- 预期收益：2%-8%，对 `crypto/h-4/huffman` 等 helper-heavy 用例有帮助。
- 风险点：代码膨胀、递归误内联、phi/return 合流复杂。
- 功能测试：多块 if-return helper、纯函数、多调用点、递归负例。
- 性能测试：2026 perf，记录代码尺寸和编译耗时。
- 建议执行顺序：B1/B2 后做小成本模型版本。
- 是否建议实现：建议。

### A2 InlineStore / 跨块 store-to-load forwarding

- 优先级：P1。
- 当前项目状态：已有 `LocalStoreForwardPass` 和 `DLEPass`，但 LocalStoreForward 只在同一基本块 exact pointer 上前递，DLE 遇到 call/unknown alias 会清空。
- hw 参考：`Testing/Hycompiler/src/opt/InlineStore.cpp`、`Testing/Hycompiler/src/opt/DLE.cpp`、`Testing/Hycompiler/src/opt/DSE.cpp`。
- 当前问题：一些 load 的最近 store 支配 load，且中间无 clobber，但当前局部 pass 无法跨块前递。
- 优化目标：用支配树 + MemoryAlias 追踪最近 store，在 exact/base+offset 且无 may-alias store/call 时替换 load。
- 实现思路：先只处理同一函数内、非循环或已规范循环中的 exact location；未知 call 和指针形参全部保守 clobber。
- 涉及模块：`MemoryAlias`、`DLEPass`、`IRCFG`、`StoreInst`、`LoadInst`。
- 前置依赖：B1、B2；如果和 A1 组合，依赖 C1。
- 预期收益：1%-5%，偏向数组局部临时和参数槽。
- 风险点：alias/clobber 判断错误会直接错编；之前 unknown-offset 精确化已有段错教训。
- 功能测试：跨块 store-load、if 合流、call clobber、may alias 负例。
- 性能测试：2026 perf，重点 `many_mat_cal/sl/transpose`。
- 建议执行顺序：在 B1/B2 后作为内存 cleanup 子阶段做。
- 是否建议实现：谨慎建议。

### R3 Spill 优化 / rematerialization / FPR callee-saved

- 优先级：P1。
- 当前项目状态：图着色 RA 已可用，GPR 有 `t0-t6 + s1-s11`，COPY coalescing 和 affinity 已实现；spill 仍是对每个 use/def 插入 load/store。
- hw 参考：`Testing/Hycompiler/src/rv/RegAlloc.cpp` 的优先级、phi 偏好、spill/tidyup；也参考 Iroha 的 coalescing/regalloc 方向。
- 当前问题：D1/D2/A1 可能增加 live range；如果 spill 仍很直接，IR 优化收益会被栈流量抵消。

- 风险点：ABI 保存恢复、call clobber、FPR 调用约定错误风险高。
- 功能测试：call-heavy、float、spill 压力、大栈帧、递归。
- 性能测试：2026 perf；辅助记录 spill slot 数、reload/store 数。
- 建议执行顺序：先统计，再 rematerialize 常量/地址，最后考虑 FPR。
- 是否建议实现：建议在 D1 后复查。

### A3 只读全局/常量数组合成、DeadGlobalStore

### C2 通用 jump threading / block layout

- 优先级：P2。
- 当前项目状态：`SimplifyCFGPass` 已有常量分支折叠、phi/icmp branch 中转块折叠、不可达块删除和空跳转块 bypass；后端已有 compare-branch fusion，但无通用 layout。

- 是否建议实现：暂缓。

## 7. 建议执行顺序

建议主线：

```text
B1. ADCE + cleanup round
  -> C1. LoopSimplify / LCSSA / LoopRotate
  -> E1. MachineDCE + MachineInstCombine + StrengthReduction 子集
  -> D1. SCEV 地址递推 / loop strength reduction
  -> B2. 完整 GVN
  -> A1. 循环内存标量替换
  -> R2. Tail Call Optimization
  -> D2. 小常数循环展开
  -> B3/F1/A2/R3 按热点复查插入
```

排序理由：

- B1 先做，是为了让后续任何大优化都有 cleanup 安全网。
- C1 是 D1/D2/A1/GCM 的循环形态前置。
- E1 要早于 D1/D2，避免 perf2 中“IR 变强但后端栈流量暴涨”的回退。
- D1 直接命中当前最大热点组。
- B2/A1 在 D1 后收益更容易放大。
- R2 针对 `h-1-03`，可作为独立 P1 插入；如果短期要打单点热点，可提前到 C1 后。
- D2 最容易因代码膨胀回退，放在 cleanup/机器承接更完整之后。
