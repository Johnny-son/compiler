补充对照 `Testing/Hycompiler` 和现代编译器常规后端做法后，本轮新增一个执行判断：完整 SCEV/LoopRotate 仍是最大方向，但 perf9 的 E3 再次证明静态指令减少可能被 `mv`、live range 和 spill 吃掉。因此 perf10 先补“后端承接能力”中更小的两块：

| 方向 | hy/现代编译器做法 | 当前项目差距 | perf10 取舍 |
| --- | --- | --- | --- |
| Machine DCE | hy `RvDCE` 在 RV InstCombine 中多轮删除无 use 纯 op | 当前 MachineLocalCSE 会删除重复表达式，但没有独立死纯指令清理 | 本轮先做 M1a，若无收益或回退则撤回 |

| SCEV / loop address | hy 在 LoopRotate/LICM/SCEV/GVN 多轮闭环中做 | 当前缺成本模型，历史裸 SCEV/LCSSA 多次回退 | 本轮只保留路线，不直接做完整 SCEV |
| 机器 copy propagation | hy 后端有较完整 peephole 与 RA 配合 | perf9 E3 copy-aware CSE 明显回退 | 本轮明确不做跨 copy 的表达式传播 |

## 4. perf10 总路线

根据收益和风险，perf10 不应平均实现 OI Wiki 上的所有优化，而是按当前项目缺口排序：

```text
T. 工具与观测
  -> C. 按需循环形态补全
  -> S. SCEV / IndVars 地址递推
  -> L. 成本受控 LICM 升级
  -> M. 机器级 cleanup / strength reduction
  -> U. 小范围 unroll / unswitch 复查
```

排序原因：

- 当前简单 fold、DCE、inline 已经做过，继续加零散规则收益变窄。
- 剩余热点主要是矩阵、stencil、transpose、many_mat_cal 这类循环和地址计算密集型用例。
- 历史已经证明裸 SCEV/unroll/GCM 能过功能但会因寄存器压力回退，因此必须把 loop shape、cleanup、机器级承接放在同一条链上。
- 自动向量化、冷热分离、通用 layout 对当前后端改动太大，不适合作为 perf10 主线。

## 6. 暂缓或不做项

| 项 | 结论 | 原因 |
| --- | --- | --- |
| 全量自动向量化 | 暂不做 | 当前 IR 和 RISC-V 后端没有 RVV 类型、寄存器和指令支持；实现量远超 perf10 |
| Hot/Cold Splitting | 暂不做 | OI 性能集热点多为 tight loop，拆冷代码对 timer 帮助很小 |
| 全函数无差别 LCSSA | 暂不做 | 历史出现 timeout；只允许按需为具体候选构造 |
| 裸 GCM | 暂不做 | 历史回退，原因是 live range 拉长和寄存器压力 |
| 扩大 late inline | 暂不做 | perf9 的只读全局 load helper inline 已回退；除非先有更强成本模型 |
| 通用 magic division | 暂不做 | `/3` 已验证总分回退；只能单规则、单热点验证 |
| 语言层 `register` 支持 | 不做 | 现代编译器不应信任该提示；本项目 RA 成本模型更重要 |

## 9. 对 OI Wiki 条目的取舍结论

### M1a MachineDCE

状态：已完成，保留。

实现内容：

- 新增 `MachineDCE`，放在 `MachineLocalCSE` 之后、寄存器分配之前。
- 每轮重建 `MachineCFG` 与 `MachineLiveness`，删除无 use 的虚拟寄存器定义。
- 只处理无副作用机器指令：`COPY/LI/LA/LA_STACK` 和纯整数算术、逻辑、比较类指令。
- 不删除 load/store/call/branch，不删除带隐式定义或物理寄存器定义的指令。

### M1b MachineInstCombine

状态：已完成，保留。

实现内容：

- 新增 `MachineInstCombine`，放在 `MachineLocalCSE` 之后、`MachineDCE` 之前。
- 把后端残留的 `li + add/addw/and` 折叠为 `addi/addiw/andi`，只接受 signed 12-bit 立即数。
- 把 `addi addr, base, imm` 后所有 use 都是可折叠 load/store base 的场景合并进内存偏移。
- 地址偏移合并要求所有 use 都能折叠且新偏移仍是 signed 12-bit；否则不改，避免增加 live range 或让 legalizer 拆回去。

### 9.1 已经完成且只需维护的条目

- 常量折叠：已覆盖大部分安全基础规则。后续只补不会触碰 UB/NaN/除零的规则。
- DCE：已有 DCE/ADCE。关键不是再加一个 DCE，而是在 SCEV/unroll/inline 后形成 cleanup 小闭环。
- 函数内联：小纯函数 inline 已经有历史大收益；扩大 inline 必须用成本模型。
- 尾调用优化：self-tail-call 已覆盖最有价值的场景，通用尾调用暂不急。

### 9.2 perf10 最值得投入的条目

- IndVars/SCEV：当前剩余循环热点最需要这一类优化，预计收益最高。
- LICM 升级：需要结合 alias 和寄存器压力，不再裸外提。
- 机器级 cleanup 和 strength reduction：要承接 SCEV/LICM 产生的新 IR，避免历史回退重演。
- 按需 LoopRotate/LCSSA：本身收益小，但对 SCEV/unroll 是共同前置。

### 9.3 当前不建议投入的条目

- 自动向量化：后端缺 RVV 支撑，短期不可控。
- Hot/Cold Splitting：对当前 timer 几乎没有收益。
- 通用 LoopUnswitch 和通用 LoopUnroll：没有成本模型时容易代码膨胀。
- `register` 语言提示：不应驱动优化决策。

## 10. 下一轮建议

perf10 已完成 M1a/M1b 两个后端承接优化。下一轮不应直接写 SCEV，而是先补一个只观测不改 IR 的循环候选报告：列出每个热点函数中可识别的 induction phi、trip count、GEP stride、body 指令数、phi 数、call/store 情况。拿到这个报告后，再选择 `many_mat_cal-*`、`sl*`、`transpose*` 中最小的安全模式实现 S1。

如果 S1 引入的新临时值导致总分回退，优先回到 M1a/M1b 的机器级 cleanup 和地址折叠能力上补承接规则，而不是继续扩大 SCEV 或 unroll。
