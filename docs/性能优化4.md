1. 在本文件中列出目标、预期收益、风险和验证命令。

## 6. 执行记录

### R1 Runtime Memoization

状态：已实现；官方 RISC-V 性能复测被当前环境阻塞。

目标：

1. 找到二参 `i32 -> i32` 纯自递归函数，例如 `knapsack_naive(i, w)`。
2. 为每个候选函数创建 `seen/value/epoch` 三组内部全局对象：`seen` 和 `value` 是 `[262144 x i32]`，`epoch` 是 `i32`。
3. 在函数入口插入 memo hit 检查，命中直接返回缓存值。
4. 在每个 return 前写回缓存。
5. 在外部调用候选函数前递增 epoch，避免不同输入数据共享旧缓存。

候选过滤：

- 函数返回类型必须是 `i32`。
- 参数必须正好两个，且都是 `i32`。
- 函数内部允许调用自己，不允许调用其他用户函数或内置函数。
- 函数不能有 store，不能写全局或局部内存。
- 函数必须至少有一个基本块包含两个及以上自递归调用；这用于过滤快速幂、Collatz 这类单路径递归，避免 memo 纯变开销。
- 暂不处理浮点、数组参数、多返回值和三参递归。

预期：

- 直接降低 `knapsack_naive-*` 的指数递归时间。
- 若 memo table 和入口检查成本可控，预计总 timer 改善 15%-30%。

实现要点：

- 插入位置：`InlineSimpleFunctionPass` 之后，`ConstantFoldPass` 之前，并在 pass 后运行 `VerifyPass`。
- 索引方式：只缓存 `0 <= arg0 < 128` 且 `0 <= arg1 < 2048` 的状态，`idx = arg0 * 2048 + arg1`；越界直接走原函数体且不写回。
- 命中路径：入口检查 `seen[idx] == epoch` 后直接返回 `value[idx]`。
- 写回路径：原始 return 前重新检查参数范围，先写 `value[idx]`，再写 `seen[idx] = epoch`。
- 外部入口：非自递归调用候选函数前递增 `epoch`，避免不同输入数组或全局状态共享旧缓存。
- 成本模型修正：初版仅按“纯二参自递归”过滤，会误命中 `fft*` 的 `multiply` 和 `h-1-*` 的 `fun`，native 明显负优化；已收紧为“同一基本块至少两个自递归调用”，当前只命中 `knapsack_naive-*`。
