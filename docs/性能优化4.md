# 性能优化4：针对剩余热点的大优化路线

本文档接替 `性能优化3.md`，用于记录 perf4 阶段的调研、路线、实现顺序、测试数据和取舍结论。perf3 已经把后端寄存器、Phi lowering、copy coalescing、compare-branch fusion、栈帧返回路径和 GEP 地址前缀缓存补到一个可承接大优化的状态；perf4 不再执着零散 peephole，而是按热点占比和高分项目差距，优先推进能带来明显总分变化的结构性优化。

执行原则和前几轮一致：每个优化点先写进本文档，再按顺序实现；功能测试和性能测试通过且有正收益才提交；负优化先排查实现问题，确认方向或成本模型不合适后撤回，只保留记录；每完成或撤回一项，都重新审视热点并把新的重要候选插入到合适位置。

## 3. 高分项目对比出的缺口

| 大类 | 高分项目做法 | 我们缺失的内容 | 为什么仍影响大 |
| --- | --- | --- | --- |
| 热点算法级变换 | Sisyphus 有 `RuntimeMemoize`，高分项目普遍会对特殊热点做结构化识别 | R1 已补递归 memo；其他热点仍缺专门结构识别 | 当前总分集中在少数 case，打掉一个热点组收益远大于小 peephole |
| SCEV/闭式化 | Hy/Sisyphus 用 SCEV 理解归纳变量、trip count、线性递推 | G1 只做了一个窄模式闭式化，通用 SCEV 地址递推仍缺 | `conv2d/sl/matmul/transpose` 还有大量循环内乘加地址计算 |
| 循环结构 | Hy/Sisyphus/Iroha 有 LoopSimplify、LCSSA、LoopRotate、dedicated exits | 当前只补 preheader，复杂 exit 和旋转不足 | 后续 unroll、scalar replace、GCM 很难稳定落地 |
| 机器级 cleanup | Hy/Sisyphus 有 RISC-V `StrengthReduct`、`InstCombine`、`RvDCE` | 我们缺 liveness-aware 机器 DCE/Combine，除模降强也只做保守子集 | IR 大优化会产生新临时值，后端不清理就容易被栈流量抵消 |
| 标量全局优化 | Hy/Sisyphus 多轮 `GVN -> DCE -> Fold -> GCM -> GVN -> ADCE`，Iroha 有 `SCCP -> GVN -> DCE` | 缺 SCCP、完整 GVN、ADCE | 常量边和不可达分支收敛不够，循环优化后的 IR 胖 |
| 内存标量替换 | Sisyphus `ScalarReplace`，高分项目会把循环内固定地址 load-store 变成标量递推 | 只做局部 store-forward 和 DLE/DSE | reduce/stencil/矩阵更新热点仍有重复 load/store |

## 4. perf4 总路线

顺序原则：先打当前最大热点，再补能支撑后续大优化的共同前置；只有预期能影响热点组的优化才进入主线。

```text
R. 热点算法级 IR 变换
  -> G. 可精确证明的标量递推闭式化
  -> C. 循环结构基础补全
  -> D. SCEV 地址递推与小常数 unroll
  -> E. 机器级 cleanup 和降强
  -> B/A. 标量全局 cleanup 与内存标量替换
```

为什么 perf4 这样排：

- perf4 起始热点中 `knapsack_naive-*` 和 `conv2d-*` 已占约 49% timer；R1/G1 能直接命中这两组。
- perf2 的 SCEV/unroll/GCM 曾因后端压力回退；perf3 已补很多后端承载，所以可以重新推进，但仍要用更窄成本模型。
- 后续 C/D/E/B/A 阶段必须交替推进：循环变换产生的新 IR 需要标量和机器 cleanup 吸收，cleanup 也需要循环结构给出更稳定的分析基础。

## 9. perf4 执行记录

### R1 Runtime Memoization

状态：已实现，commit `e23bd1f`；已用 `compiler-comp` 补跑官方 RISC-V 功能和性能。

实现要点：

1. 新增 `RuntimeMemoizePass`，插入在 `InlineSimpleFunctionPass` 之后、`ConstantFoldPass` 之前。
2. 候选函数必须返回 `i32`，正好两个 `i32` 参数，无 store，无外部调用，只允许自递归。
3. 函数内必须至少有一个基本块包含两个及以上自递归 call，用于过滤快速幂、Collatz、FFT multiply 这类单路径递归。
4. 为每个候选创建 `seen/value/epoch` 三组全局对象，缓存 `0 <= arg0 < 128` 且 `0 <= arg1 < 2048` 的状态。
5. 非自递归入口调用前递增 epoch，避免不同输入数据共享旧缓存。

预期：

- 直接降低 `knapsack_naive-*` 的指数递归时间。

### G1 标量递推闭式化

状态：已实现，commit `8e7c975`；已用 `compiler-comp` 补跑官方 RISC-V 功能和性能。

新增原因：

复查 `conv2d-*` 后发现，定时区内 `init_matrix` 大量调用 `get_random()`，而 `get_random()` 的主体是精确可闭式化的单全局递推：

```c
int n = state % 2048;
while (i < n) {
    state = (state + 128) % 65535;
    i = i + 1;
}
state = state % 65535;
```

当 `n > 0` 时，循环等价于 `state = (state + n * 128) % 65535`；当 `n <= 0` 时必须保留零迭代语义，直接走原 exit 的 `state % 65535`。这是比通用 C1 更直接的高收益 SCEV 子问题，因此插入为 R1 后的下一项。

实现要点：

1. 新增 `LoopClosedFormPass`，接在 `LoopCanonicalizePass` 后，随后运行 `SimplifyCFGPass`。
2. 只处理单 preheader、单 header、单 latch/body、单 exit 的自然循环。
3. header 形如 `i = phi [0, preheader], [i + 1, latch]`，条件为 `i < n`。
4. latch/body 只能包含一次 `load g`、`add +C`、`srem %M`、`store g`、`i + 1` 和无副作用计算/分支。
5. `g` 必须是同一个 `i32` 全局变量，`C` 和 `M` 必须是正整数常量；exit 暂不处理 phi。
6. 闭式化前检查 `(n_upper - 1) * C + (M - 1)` 不超过 `i32` 正上界，避免比原循环更容易溢出。

预期：

- 直接减少 `conv2d-*` 初始化阶段的内层随机循环。
- 匹配范围窄时，收益应明显大于新增分支和乘法成本。
