当前优化能力汇总：

| 层级 | 已有内容 | 判断 |

## 2. hy 已实现的关键优化

参考项目：`Testing/Hycompiler`。

重点 pipeline：

```text
structured pre-opt
  -> FlattenCFG
  -> GVN/DCE/Inline
  -> Mem2Reg
  -> Alias/DSE/DLE/GVN
  -> CanonicalizeLoop/LoopRotate/LICM/ConstLoopUnroll/SCEV/ADCE/GVN
  -> RegularFold/DCE/GVN/SimplifyCFG/Alias/DSE/DLE/Select/GCM/ADCE
  -> LateInline
  -> InlineStore/SynthConstArray/GCM/GVN
  -> 3 rounds of CanonicalizeLoop/LICM/SCEV/RemoveEmptyLoop/GVN/Fold
  -> Final ADCE/SimplifyCFG/InstSchedule
  -> RISC-V Lower/StrengthReduct/InstCombine/RvDCE/GVN/RegAlloc
```

hy 对照出的关键差距：

| 大类 | hy 做法 | 当前差距 | 本轮判断 |
| --- | --- | --- | --- |
| Cleanup 闭环 | 大优化后多轮 `GVN/Fold/ADCE/SimplifyCFG` | 当前只有固定两段 cleanup，缺 ADCE | 本轮优先做窄 ADCE，避免后续优化产物堆积 |
| GVN | 支配树 value numbering，配合 ADCE | 当前 LocalCSE 已有 value number，但 phi/死环清理不足 | 本轮不重写 GVN，先补 cleanup |
| 循环/SCEV | LoopRotate、SCEV、ConstLoopUnroll、多轮 loop cleanup | 当前缺通用 SCEV；历史裸上容易回退 | 暂缓完整 SCEV，先做可控的低风险后端/cleanup |
| 内存优化 | Alias/DSE/DLE 多轮、InlineStore、SynthConstArray | 当前内存优化保守，跨块和循环内标量替换缺失 | 暂缓高风险内存标量替换 |
| LateInline | 较高阈值 late inline 后继续 cleanup | 当前只有前期小纯函数 inline | 本轮作为候选，需用性能决定是否保留 |
| RISC-V 后端 | StrengthReduct、InstCombine、RvDCE | 当前规则散落在 selector，除模降强仍浅 | 本轮选择安全的 2 的幂除模降强子集 |

本轮只执行下列优化，保证可以逐项实现、测试、记录和提交。完整 SCEV、GCM、全函数 LCSSA、循环内存标量替换等仍保留为后续方向，不放入本轮执行清单。

| 阶段 | 优化项 | 优先级 | 实现思路 | 预计收益 | 风险与取舍 |
| --- | --- | --- | --- | --- | --- |
| B1 | 窄 ADCE cleanup | P0 | 新增 ADCE：从 terminator、store、call、return、被分支使用的条件反向标记 live，只删除纯计算/phi/load 的死子图；接在末尾 DCE 前后验证 | 1%-5%，主要清理 GVN/inline/loop 后的死 phi 和死计算 | 如果删除 load 导致后端压力变化或语义边界不稳，撤回 |
| E1 | RISC-V 2 的幂除模降强 | P0 | 在 selector 中把 `sdiv/srem x, +/-2^k` 降为 `srai/andi/add/sub` 组合，保持 C 的向零取整和有符号余数语义；优先命中 `%2`、`/2`、`/4`、`%32` 等热点 | 2%-8%，重点 `crypto*`、`huffman-*`、`h-4-*`、排序/矩阵中的固定除模 | signed 语义复杂，必须功能全过；若总分无收益则撤回 |
| F1 | Late pure inline + cleanup | P1 | 在现有小纯函数 inline 基础上，增加 late 阶段较高阈值纯函数 inline，随后跑 Fold/CSE/ADCE/DCE；只允许无 load/store/call 的单块函数 | 1%-6%，主要减少 helper 调用和暴露常量/表达式给 GVN | 代码膨胀和寄存器压力可能回退；负收益撤回 |
| C1 | 窄 RISC-V 常量乘法降强 | P1 | 根据 E1/F1 后热点追加：只把 `x * (2^n + 1)` 和 `x * (2^n - 1)` 改成 `slli + addw/subw`，保持最多两条算术指令替代 `li + mulw` | 1%-4%，重点 `many_mat_cal-*` 的 `*3`、`crypto*` 的 `*5/*7`、`h-4-*` 的小常数乘法 | 不展开 `*1001` 等多项式，避免增加寄存器压力；若矩阵/stencil 回退则撤回 |
| C2 | RISC-V `%2` 判零分支降强 | P1 | 只识别 `icmp eq/ne (srem x, +/-2), 0` 且结果仅用于分支的模式，后端直接发 `andi 1 + beq/bne`，并跳过原 `remw` 和中间 `icmp` | 1%-3%，重点 `matmul2` 的 `%2 == 0` 热分支 | 全量 `%2^k` 判零命中 `transpose2 %4` 后总分不稳，最终只保留 `%2` 子集 |
| 复查机制 | 按热点复查后追加的重要优化 | P1 | 每完成一个阶段后，根据最新 CSV 热点和 IR/pass 统计判断是否存在仍应加入本轮的关键优化；只追加预计能影响多个热点组的方案 | 不预设 | 只有明确必要时才追加到本文档并执行 |

## 5. 暂缓项

| 优化 | 暂缓原因 |
| --- | --- |
| 完整 SCEV 地址递推 | 历史候选在后端压力不足时明显回退；当前先补 ADCE 和 RV 降强，再根据热点决定是否小范围追加 |
| 全函数 LCSSA / LoopRotate | 历史 LCSSA 导致 timeout；只能作为某个具体 SCEV/A1 候选的按需修补 |
| GCM | 历史上拉长 live range 后回退；没有寄存器压力模型前不做 |
| 循环内存标量替换 | alias、exit 写回和寄存器压力风险高，放到 SCEV/ADCE 稳定后 |
| 裸 MachineDCE / offset combine | 历史机器 cleanup 子集有负优化；本轮不裸上 |

### C1 窄 RISC-V 常量乘法降强

追加原因：B1 后热点仍集中在 `many_mat_cal-*`、`sl2`、`transpose2`、`matmul2`、`crypto-*`。E1/F1 的数据说明“多指令替换除模”和“扩大 inline”都容易放大寄存器压力；相比之下，`x * 3`、`x * 5`、`x * 7` 这类常量乘法可以用最多两条算术指令替代当前的 `li + mulw`，更贴近热点且风险更窄。

实现摘要：

- 尝试把正数因子 `2^n + 1` 改成 `slli + addw`。
- 尝试把正数因子 `2^n - 1` 改成 `slli + subw`。
- 不展开 `*1001` 等多项式，避免大幅增加指令数。

构建与正确性：构建通过；ASM `140/140`；IR `239/239`；perf 正确性 `60/60`。

性能：

| 文件 | timer 总和 | wall 总和 | 相对 B1 rerun |
| --- | ---: | ---: | --- |
| `Testing/perf8-c1-shiftadd-mul.csv` | 3510 | 7796 | +442 ms |

主要回退包括 `shuffle1`（+126 ms）、`01_mm3`（+162 ms）、`sl1/sl2`（+35/+29 ms）、`h-4-03`（+27 ms）。结论：当前后端/寄存器分配下，两条依赖算术指令替代 `li + mulw` 并不划算，还拉长 live range，源码已撤回，不采用。

### C2 RISC-V `%2` 判零分支降强

状态：已完成并保留。

追加原因：完整 E1 的 `sdiv/srem` 降强会生成多条指令并回退，但热点中仍有大量只用于分支判零的 `% 2^k`：例如 `crypto-1` 的 `%4/%16/%64/%256`、`matmul2` 的 `%2 == 0`、`transpose2` 的 `%4 == 0`。对任意有符号整数，`x % 2^k == 0` 等价于 `(x & (2^k - 1)) == 0`，因此可以只在分支发 `and + beq/bne`，并跳过原 `remw` 和 `icmp`。

执行中先尝试了全量 `% 2^k` 判零：

| 文件 | timer 总和 | wall 总和 | 结论 |
| --- | ---: | ---: | --- |
| `Testing/perf8-c2-modzero-branch.csv` | 2983 | 6930 | run1 明显改善 |
| `Testing/perf8-c2-modzero-branch-rerun.csv` | 3102 | 7040 | run2 回到 B1 附近 |
| `Testing/perf8-c2-modzero-branch-third.csv` | 3161 | 7070 | run3 回退 |

汇编审计显示全量 C2 只实际改变 `matmul2` 和 `transpose2`：`matmul2` 的 `%2 == 0` 从 `li 2; remw` 变成 `andi 1`，`transpose2` 的 `%4 == 0` 从 `li 4; remw` 变成 `andi 3`；`shuffle*`、`sl*`、`many_mat_cal-*`、`crypto-*` 汇编未变。`matmul2` 三轮稳定改善，但 `transpose2` 数据不稳定，因此最终收窄为只处理 `%2` 判零。

最终实现摘要：

- 只匹配 `icmp eq/ne (srem x, +/-2), 0`。
- 要求 `srem` 的所有 use 都是这种 `icmp`，且每个 `icmp` 都只被条件分支使用。
- 翻译 `srem` 时若确认已被分支融合，则跳过 `remw`。
- 翻译分支时生成 `andi value, 1` 后直接 `beq/bne` 到 true label。
